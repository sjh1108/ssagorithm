## 내가 이해한 문제

가이드:

- 프로세스의 순서 및 프로세스의 우선순위
- 우리가 순서를 알고 싶은 프로세스의 인덱스

한번 처리된 프로세스는 다시는 보지 않는다.

가장 우선순위가 높은 프로세스를 먼저 처리하고
그 다음에 그 다음 우선순위의 프로세스를 처리한다.

만약 꺼낸 큐가 우선순위가 아니라면 다시 큐에 넣어준다

최종적으로는 우리는 우리가 순서를 알고 싶은 프로세스의 인덱스를 처리한다.

[2,1,3,2], location = 2 기준

인덱스 기준 처리 ()는 우선순위 정도
0(2), 1(1) 패스
2(3) 처리
3(2) 처리
0(2) 처리
1(1) 처리
따라서 첫번째에 처리 되었으므로 1리턴

처리하고 우리가 알고 싶었던 프로세스의 처리 순서를 리턴


## 상태

- int order 처리 순서 리턴용
- Deque<Node> dq 처리안된 프로세스 대기 큐
- priorityque pq 가중치 별 정렬 큐 (내림차순)

- Node 현재 큐 인덱스의 값에서 원래 인덱스, 가중치 두가지를 저장


## 전이

dq.peek()으로 현재 프로세스를 확인하고 pq.peek()으로 가장 높은 우선순위를 확인한다.

만약 가중치가 같다면 dq, pq 모두 poll
order +=1


만약 같지 않다면
dq에서 poll한 프로세스를 다시 add한다.


## 제약

dq의 가중치와 pq의 가중치가 같아야 프로세스 제거가 가능함

만약 제거시에 처리 요청된 index가 나온다면 반복 종료

## 탐색 공간 및 복잡도

가이드:
- 입력의 최대 크기는 얼마인가? 최대 100
- 반복 한 번에 처리하는 대상은 무엇인가? 큐의 맨 앞 프로세스 1개
- 대상 하나를 확인할 때 다른 전체 대상을 다시 검사하는가? no, pq.peek()으로 확인
- 한 대상이 여러 번 대기열에 들어갈 수 있는가? yes
- 반복문은 최악의 경우 몇 번 실행되는가? n + (n-1) + ... + 1
- 반복 한 번의 비용은 얼마인가? 큐 이동 O(1), pq 제거 O(log n)
- 전체 시간 복잡도는 얼마인가? O(n²)
- 제한 안에서 실행 가능한가? yes
