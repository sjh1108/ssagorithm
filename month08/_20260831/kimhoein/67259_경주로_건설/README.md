- 코드: [경주로_건설.java](경주로_건설.java)

로컬 검증 결과이며, 프로그래머스 전체 채점 통과를 확인한 것은 아니다.

## 목표

벽을 피해서 `(0, 0)`에서 `(N - 1, N - 1)`까지 경주로를 건설하는 최소 비용을 구한다.
인접한 칸으로 이동할 때 직선 도로 비용 100원이 들고, 진행 축이 바뀌면 코너 비용 500원이 추가된다.

## 상태

```text
dist[x][y][horizon]
= (x, y)에 horizon 방향으로 진입했을 때 현재까지 발견한 최소 건설 비용

horizon = 0: 세로 방향으로 진입
horizon = 1: 가로 방향으로 진입
```

코드에서 `x`는 행, `y`는 열이다. 같은 위치라도 가로로 들어왔는지 세로로 들어왔는지에 따라 다음 이동 비용이 달라진다.
위치별 비용 하나만 저장하지 않고 방향별 비용 두 개를 저장한다.

우선순위 큐의 `Node`는 현재 위치, 진입 방향, 해당 경로의 누적 비용을 가지고 있다.
`node.dist`는 큐에 넣을 당시의 비용이고, `dist` 배열은 이후에 더 작은 값으로 갱신될 수 있다.

## 전이

현재 위치에서 상하좌우의 다음 칸 `(dx, dy)`를 확인한다.

1. 배열 범위를 벗어나거나 벽이면 건너뛴다.
2. 이전 진입 축과 같은 축으로 이동하면 100원을 더한다.
3. 다른 축으로 이동하면 600원을 더하고 `horizon`을 바꾼다.
4. 도착 상태의 비용을 갱신하고 우선순위 큐에 넣는다.

```text
같은 축: nextCost = node.dist + 100
다른 축: nextCost = node.dist + 100 + 500
```

원본 코드의 갱신 조건은 다음과 같다.

```text
기존 dist < nextCost이면 건너뛴다.
그렇지 않으면 dist를 nextCost로 저장하고 큐에 넣는다.
```

따라서 더 작은 비용뿐 아니라 같은 비용으로 도착한 경우도 다시 큐에 들어간다.
원본 로직은 보존했으며, 같은 상태의 중복 처리를 줄이려면 `nextCost < 기존 dist`인 경우만 갱신하도록 개선할 수 있다.

## 종료 조건

우선순위 큐가 비면 탐색을 종료한다.
꺼낸 경로의 비용보다 `dist`에 저장된 비용이 작으면 이미 더 좋은 경로를 찾은 것이므로 그 항목은 건너뛴다.

도착점에 가로 또는 세로로 도착할 수 있으므로 두 값 중 작은 값을 반환한다.

```text
min(dist[N - 1][N - 1][0], dist[N - 1][N - 1][1])
```

## 초기화

- 전체 `dist`를 `Integer.MAX_VALUE`로 초기화한다.
- 출발점의 두 방향 비용을 0으로 설정한다.
- 오른쪽 `(0, 1)`이 비어 있으면 가로 방향, 비용 100으로 큐에 넣는다.
- 아래쪽 `(1, 0)`이 비어 있으면 세로 방향, 비용 100으로 큐에 넣는다.

첫 이동에는 이전 방향이 없으므로 코너 비용을 붙이지 않는다.
문제에서 `N >= 3`이 보장되므로 이 두 칸에 접근할 수 있다.

## 탐색 공간 및 복잡도

```text
상태 개수: 2 × N²
각 상태의 다음 이동 후보: 최대 4개
거리 배열 공간: O(N²)
```

더 작은 비용일 때만 큐에 넣는 일반적인 다익스트라 구현이라면 시간 복잡도는 `O(N² log N)`, 공간 복잡도는 `O(N²)`이다.

다만 현재 원본은 같은 비용의 상태도 다시 넣으므로 위 시간 복잡도를 그대로 보장할 수 없다.
전체 큐 삽입 횟수를 중복 포함 `Q`라고 하면 원본의 비용은 다음과 같이 표현할 수 있다.

```text
시간 복잡도: O(N² + Q log(Q + 1))
공간 복잡도 상한: O(N² + Q)
```

## 손으로 실행해보기

```text
board =
[0, 0, 0]
[0, 0, 0]
[0, 0, 0]

초기 큐:
(0, 1, 가로, 100)
(1, 0, 세로, 100)

(0, 1, 가로, 100)에서:
→ (0, 2, 가로, 200): 직선 이동
→ (1, 1, 세로, 700): 코너를 포함한 이동

최소 비용 경로 중 하나:
(0, 0) → (0, 1) → (0, 2) → (1, 2) → (2, 2)
누적 비용: 0 → 100 → 200 → 800 → 900

반환값: 900
```

위 예시는 설명할 경로만 발췌했다. 실제 탐색은 큐에 있는 다른 경로도 비용 순서대로 확인한다.

## 풀이 후 배운 점

- 다음 이동의 비용에 영향을 주는 진입 방향도 상태에 포함해야 한다.
- `dist` 배열과 큐에 남아 있는 과거 비용을 비교하여 불필요한 탐색을 건너뛸 수 있다.
- 최단 비용만 구할 때는 같은 상태에 같은 비용으로 도착한 경로를 다시 처리할 필요가 없다.
- 첫 이동에는 코너가 없다는 조건을 초기화에서 따로 표현할 수 있다.
