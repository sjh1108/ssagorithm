## 목표

1번 마을에서 출발하여 최단 이동 시간이 `K` 이하인 마을의 개수를 구한다.
출발 마을인 1번 마을도 거리 0으로 결과에 포함된다.

## 상태

```text
dist[i]
= 1번 마을에서 i번 마을까지 현재까지 발견한 최단 이동 시간
```

- `roads[i]`: `i`번 마을에 연결된 다음 마을과 도로별 이동 시간
- 큐의 `node.id`: 현재 확인할 마을
- 큐의 `node.dist`: 이 경로로 현재 마을까지 도착한 누적 시간
- `answer`: 최단거리 계산 후 `K` 이하인 마을의 개수

인접 리스트의 `Node.dist`는 간선 하나의 시간이고, 큐에 들어 있는 `Node.dist`는 누적 시간이다.
현재 위치에 따라 다음 도로가 정해지므로 거리 배열은 마을 번호별로 저장한다.

## 전이

현재 마을에서 연결된 도로 하나를 통해 다음 마을로 이동하는 경우를 확인한다.

```text
nextTime = node.dist + curNode.dist

nextTime < dist[curNode.id]이면:
dist[curNode.id] = nextTime
다음 마을과 nextTime을 우선순위 큐에 넣는다.
```

이미 더 짧거나 같은 시간이 기록되어 있으면 갱신하지 않는다.
도로별 이동 시간이 다르므로 단순히 이동한 도로 수가 아니라 누적 시간이 작은 상태부터 확인한다.

두 마을 사이에 여러 도로가 있어도 인접 리스트에 모두 저장한다.
더 짧은 시간을 만드는 도로만 최단거리 갱신에 반영된다.

## 종료 조건

우선순위 큐가 비면 다익스트라를 종료한다.
꺼낸 경로의 시간이 현재 `dist`보다 크면 이미 더 좋은 경로를 찾은 것이므로 건너뛴다.

이후 1번부터 `N`번까지 확인하여 `dist[i] <= K`인 마을을 세고 반환한다.
정확히 `K`가 걸리는 마을도 포함한다.

## 초기화

- 인접 리스트와 거리 배열을 `N + 1` 크기로 만든다.
- 각 도로 `(a, b, c)`를 `a → b`, `b → a` 양방향으로 저장한다.
- 전체 거리를 `Integer.MAX_VALUE`로 초기화한다.
- `dist[1] = 0`으로 설정한다.
- 큐에 `(1, 0)`을 넣고 시작한다.

## 탐색 공간 및 복잡도

`V`는 마을 수, `E`는 입력 도로 수다. 같은 마을 쌍에 여러 도로가 있을 수 있다.

```text
마을 상태: V개
인접 리스트 항목: 2E개
최종 거리 조건 확인: V개
```

현재처럼 개선된 거리를 큐에 추가하고 오래된 항목을 건너뛰는 구현은 큐 항목을 최대 `O(E)`개 생성한다.

```text
시간 복잡도: O((V + E) log(E + 1))
공간 복잡도: O(V + E)
```

## 손으로 실행해보기

```text
N = 5, K = 3
road = [[1, 2, 1], [2, 3, 3], [5, 2, 2],
        [1, 4, 2], [5, 3, 1], [5, 4, 2]]

시작: dist[1] = 0, 나머지는 무한대

1번을 꺼냄:
→ 2번까지 1, 4번까지 2로 갱신

2번을 꺼냄:
→ 3번까지 4, 5번까지 3으로 갱신

4번을 꺼냄:
→ 5번까지 4가 되므로 기존 3을 유지

5번을 꺼냄:
→ 3번까지 4가 되므로 기존 4를 유지

최종 거리(1~5번): [0, 1, 4, 2, 3]
K 이하인 마을: 1, 2, 4, 5
반환값: 4
```

## 풀이 후 배운 점

- 가중치가 서로 다른 양수 간선에서는 누적 비용을 기준으로 다익스트라를 사용할 수 있다.
- 같은 마을이 큐에 여러 번 들어갈 수 있으므로 꺼낸 비용이 오래된 값인지 확인해야 한다.
- 최단거리 계산과 `K` 이하인 마을을 세는 작업을 나누면 목적이 명확해진다.
- 출발점과 경계값 `dist[i] == K`도 결과에 포함해야 한다.
