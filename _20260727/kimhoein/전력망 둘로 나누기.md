## 처음 작성한 모델링

### 내가 이해한 문제

송전망을 어디를 끊고 어떻게 이어야 최선의 결과 값을 찾을 수 있는지 잘 모르겠다.

다만 트리 구조라는 힌트를 주었으므로 DFS가 `O(n)`이고 송전망 끊기가 `O(n)`이라고 한다면, 100^100은 10000이므로 시간적으로 문제가 없어 완전탐색을 수행하고자 한다.

### 상태

- 0~n-1 송전망 개수
- DFS할 때 쓸 `visit[]`: 방문했는지 안 했는지
- `count`: DFS할 때 송전탑 개수
- 현재까지 가장 낮은 송전탑의 차이 변수

### 전이

- 아직 방문하지 않았다면 `visit = true`
- 아직 방문하지 않았다면 카운트를 증가시키고 DFS를 실행해서 한 송전탑에서 연결된 모든 송전탑 개수를 센다.
- 하나의 송전선 확인이 끝나면 방문과 카운트를 모두 초기화한다.

### 제약

- 이미 방문한 곳은 건너뛴다.

### 목표

- 특정 송전선을 끊었을 때?

### 내 풀이 방향

- 0~n-1 `for`문 생성
- 방문하지 않았다면 방문 처리
- 네트워크 카운트 증가
- DFS 또는 BFS를 시작해서 연결된 것을 모두 방문 처리
- 탐색 후 다시 `for`문 진행

### 막힌 부분

- 심한 건 아닌데 DFS 부분에서 신경 써야 할 조건들이 있었는데 모델링에는 없어서 다른 구간보다 조금 더 지체된 문제가 존재했다.

## 다시 작성한 모델링

### 내가 이해한 문제

송전망을 어디를 끊고 어떻게 이어야 최선의 결과 값을 찾을 수 있는지 잘 모르겠다.

다만 트리 구조라는 힌트를 주었으므로 DFS가 `O(n)`이고 송전망 끊기가 `O(n)`이라고 한다면, 100*100은 10000이므로 시간적으로 문제가 없어 완전탐색을 수행하고자 한다.

### 상태

- 0~n-1 `Ecount`: 현재 방문한 송전탑 개수
- DFS할 때 쓸 `visit[]`: 방문했는지 안 했는지
- 현재까지 가장 낮은 송전탑의 차이 변수 `minCount`
- `current`: 현재 위치한 송전탑 번호

### 전이

- 외부 송전망 하나하나를 직접 처리
- 내부 잘린 송전망 양 끝단 중 하나에서 출발해서 송전탑 탐색
- 아직 방문하지 않았다면 `visit = true`
- 아직 방문하지 않았다면 카운트를 증가시키고 DFS를 실행해서 한 송전탑에서 연결된 모든 송전탑 개수를 센다.
- 하나의 송전선 확인이 끝나면 방문과 카운트를 모두 초기화한다.

### 제약

- 이미 방문한 곳은 건너뛴다.
- 잘린 전선은 건너지 않는다.

### 목표

- 특정 송전선을 끊었을 때?
- 두 개로 나뉜 송전망 내부의 송전탑 개수의 차가 최소인 곳을 찾기
- `Math.abs(전체 송전선 - 연결된 송전망 개수 * 2)`

### 내 풀이 방향

- 0~n-1 `for`문 생성
- 의도적으로 건너 칸을 방문 처리해서 전선을 끊음
- 방문 초기화
- 카운트 초기화
- DFS 또는 BFS를 시작해서 연결된 것을 모두 방문 처리
- `Math.abs(전체 송전선 - 연결된 송전망 개수 * 2)`
- `for`문 진행

## 피드백 반영 모델링

### 내가 이해한 문제

전력망은 `n`개의 송전탑과 `n-1`개의 전선으로 이루어진 트리다. 전선 하나를 선택해 끊으면 전력망이 두 부분으로 나뉜다. 모든 전선을 하나씩 끊어 보고, 두 전력망의 송전탑 개수 차이가 최소가 되는 값을 반환한다. 전선을 끊은 뒤 다시 잇는 문제는 아니다.

완전탐색의 후보는 `n-1`개의 전선이다. 후보 하나를 검사할 때 DFS로 한쪽 전력망의 송전탑을 세므로 `O(n)`이 필요하다. 전체 예상 비용은 `O(n) × O(n) = O(n²)`이고, `n`이 최대 100이므로 실행 가능하다.

### 상태

> 지금 어디에 있고, 무엇을 알고 있는가?

#### 후보 상태

- 현재 끊어 볼 전선의 두 끝점 `u`, `v`

#### DFS 상태

- `current`: 현재 DFS가 확인하고 있는 송전탑
- `visit[]`: 이번 전선 후보를 검사하면서 방문한 송전탑

#### 계산값

- `Ecount`: 현재 한쪽 전력망에서 센 송전탑 개수

#### 정답 누적값

- `minCount`: 지금까지 확인한 두 전력망의 송전탑 개수 차이 중 최솟값

### 전이

> 다음 상황으로 가기 위해 무엇을 선택하거나 바꾸는가?

#### 바깥 전이

- `wires`에서 끊어 볼 전선 하나를 선택한다.

#### 안쪽 전이

- 현재 송전탑 `current`에 연결된 송전탑 `next` 하나를 확인한다.
- `next`가 아직 방문되지 않았다면 방문 처리하고, `next`를 현재 송전탑으로 하여 DFS를 계속한다.
- `for`문은 가능한 `next` 후보를 열거하고, `dfs(next)` 호출이 실제 상태 전이를 수행한다.

### 제약

> 그 선택을 하지 못하게 막는 조건은 무엇인가?

- 이미 방문한 송전탑으로는 이동하지 않는다.
- 이번에 끊기로 한 전선은 건너지 않는다.
- 현재 구현에서는 전선이 `u-v`일 때 `u`에서 시작하고 `v`를 미리 차단한다.
- 트리는 두 송전탑 사이의 경로가 하나뿐이므로 `v`를 차단하면 `u-v` 전선을 끊은 효과가 난다.

### 후보별 초기화

- 새로운 전선을 검사할 때마다 `visit[]`을 새로 만든다.
- 새로운 전선을 검사할 때마다 `Ecount`를 0으로 초기화한다.
- DFS 시작점은 다시 세지 않도록 방문 처리한다.

### 목표

> 어떤 값을 계산하고 그중 무엇을 답으로 선택하는가?

- 한쪽 전력망의 송전탑 수는 `Ecount`다.
- 다른 쪽 전력망의 송전탑 수는 `n - Ecount`다.
- 후보 하나의 차이는 `|Ecount - (n - Ecount)| = |n - 2 × Ecount|`다.
- 모든 전선을 확인하여 `Math.abs(n - Ecount * 2)`의 최솟값을 반환한다.

### 탐색 공간

- 선택 대상: 끊을 전선
- 후보 하나의 형태: `wires[i]`에 저장된 두 끝점 `u`, `v`
- 전체 후보 수: `wires.length = n-1`
- 후보 하나의 검사 비용: DFS `O(n)`
- 전체 예상 비용: `O(n²)`

### 내 풀이 방향

1. 전선 정보를 양방향 인접 리스트로 저장한다.
2. `wires`의 모든 전선을 하나씩 끊어 본다.
3. 후보마다 `visit[]`과 `Ecount`를 초기화한다.
4. 끊을 전선의 한쪽 끝점에서 DFS를 시작하고 반대쪽 끝점을 차단한다.
5. DFS로 한쪽 전력망의 송전탑 수를 센다.
6. `Math.abs(n - Ecount * 2)`로 두 전력망의 송전탑 수 차이를 계산한다.
7. 모든 후보의 결과 중 최솟값을 반환한다.

## 막힌 부분

- 입력에 `[1, 3]` 하나만 주어졌을 때 방향이 한쪽뿐이라고 생각했지만, 이것은 방향 없는 전선 하나를 뜻한다.
- 인접 리스트에 `a → b`, `b → a`를 모두 저장하므로 DFS에서 시작점을 방문 처리하지 않으면 부모 방향으로 돌아와 시작점을 중복 집계한다.
- `visit[start] = true`는 시작점 재방문 방지이고, `visit[v] = true`는 끊은 전선의 반대쪽 차단이므로 역할이 다르다.
- `for`문 자체가 전이가 아니라, `for`문은 이동 후보를 확인하고 `dfs(next)`가 실제 전이를 수행한다.

## 배운 점

- 문제의 전선은 방향 없는 간선이며, 입력 한 줄을 양방향 인접 리스트에 두 번 저장한다.
- DFS의 현재 송전탑은 다음 이동 후보를 결정하므로 상태다.
- 상태는 반드시 필드일 필요가 없으며 재귀 매개변수로 전달할 수도 있다.
- 새로운 후보를 검사하기 위한 초기화는 전이나 제약과 구분한다.
- 송전탑, 전선, 전력망의 의미와 각각의 개수를 구분한다.
- 완전탐색은 `전체 후보 수 × 후보 하나의 검사 비용`으로 실행 가능성을 판단한다.
