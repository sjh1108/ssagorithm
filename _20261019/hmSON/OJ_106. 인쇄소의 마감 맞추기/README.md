# OJ_106. 인쇄소의 마감 맞추기

마감이 정해진 주문들 중 일부만 받아 한 대의 인쇄기로 처리할 때, **받는 주문 수를 최대화**하고 그 중에서도 **처리 시간 합을 최소화**해야 함

요구사항이 두 겹이지만 두 번째는 첫 번째에 종속됨<br>
개수를 줄여서 시간 합을 낮추는 것은 허용되지 않으므로, 개수를 유지한 채 시간만 줄이는 방법을 찾아야 함

> 처음에는 마감 역순으로 훑으며 처리 시간이 작은 주문부터 채우는 방식을 시도했으나 실패<br>
> 한 번 담은 주문을 되돌릴 수 없는 방식에 의해, 개수가 같을 때 더 싼 조합으로 교체하는 경우를 놓치기 때문

## 1. 접근 전환 - 담았다가 버리기
"**일단 하나씩 전부 담고, 마감을 지킬 수 없는 순간이 올 때마다 하나씩 버리는**" 전략으로 전환

> **마감 오름차순으로 순회하며 주문을 누적시키다가, 누적 시간이 현재 마감을 넘으면 이미 담은 것 중 처리 시간이 가장 긴 주문을 버린다**


## 2. 교체만으로 두 요구사항을 동시에 해결하는 이유
버리기는 **주문 하나를 넣고 특정 주문 하나를 빼는 쌍**으로 일어나므로 받은 주문 수가 변하지 않음

- 마감을 넘기지 않으면 그대로 담아 **개수가 1 증가**
- 마감을 넘기면 하나를 버려 **개수는 유지하고 시간 합만 감소**

따라서 버리는 과정에서도 1순위인 "주문 수 최대"를 해치지 않으면서 2순위인 "시간 합 최소"를 챙길 수 있게 됨


## 3. 최대 힙
버릴 대상을 매번 선형 탐색하면 $O(N^2)$이 되므로, **처리 시간이 가장 긴 주문을 즉시 꺼낼 수 있는 구조**가 필요

> `PriorityQueue<Long>(Comparator.reverseOrder())`

담긴 주문들의 처리 시간을 최대 힙으로 관리하면 삽입과 제거 모두 $O(\log N)$<br>
또한 **힙의 크기가 곧 받은 주문의 수**이므로 별도의 카운팅이 불필요


## 4. 복잡도
- 정렬 : $O(N \log N)$
- 순회 : 주문마다 힙 삽입 1회, 최대 제거 1회 → $O(N \log N)$

전체 $O(N \log N)$, `N = 200,000` 기준 약 $3.5 \times 10^6$ 수준<br>
공간 복잡도는 입력 배열과 힙으로 $O(N)$
