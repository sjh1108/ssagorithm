## 1. 내가 이해한 문제

- 입력으로 무엇을 받는가? 사람들의 몸무게 배열과 보트에 태울 수 있는 최대 무게
- 무엇을 반환해야 하는가? 모든 사람을 구조하는 데 필요한 구명보트의 최소 개수
- 핵심 규칙은 무엇인가? 최대 무게를 넘으면 안 되고, 한 보트에는 최대 2명까지 탈 수 있다.
- 한 번만 사용하는 대상인지, 순서가 고정인지 확인했는가? 한 번 구조한 사람은 다시 보지 않으며 태우는 순서는 자유다.

한 문장 목표:

> 모든 사람을 무게 제한과 최대 탑승 인원을 지키면서 구조하는 데 필요한 구명보트의 최소 개수를 구한다.

가장 무거운 사람은 반드시 현재 보트에 태운다.
가장 가벼운 사람과도 함께 탈 수 없다면 다른 누구와도 함께 탈 수 없으므로 혼자 태운다.
함께 탈 수 있다면 가장 가벼운 사람과 태워 더 무거운 사람들을 이후 조합에 남긴다.

## 2. 상태

| 상태 | 의미 | 초기값 | 변경 시점 |
|---|---|---:|---|
| `people` | 오름차순으로 정렬한 몸무게 배열 | 입력 배열 정렬 | 변경하지 않음 |
| `front_index` | 가장 가벼운 남은 사람의 인덱스 | `0` | 함께 탑승할 때 `+1` |
| `back_index` | 가장 무거운 남은 사람의 인덱스 | `people.length - 1` | 매 보트마다 `-1` |
| `count` | 사용한 보트 수 | `0` | 매 보트마다 `+1` |

## 3. 전이

```text
현재 확인할 대상:
가장 가벼운 사람과 가장 무거운 사람

검사할 조건:
people[front_index] + people[back_index] <= limit

조건이 참이면:
두 사람을 함께 태운다.
front_index++, back_index--

조건이 거짓이면:
가장 무거운 사람만 태운다.
back_index--

공통 전이:
count++
```

한 명만 남은 경우에는 그 사람을 보트에 태우고 `count++`한 뒤 종료한다.

## 4. 종료 조건

```text
성공 조건: front_index > back_index가 되어 모든 사람을 처리하면 종료한다.
한 명만 남은 경우: front_index == back_index이면 보트 한 척을 추가하고 종료한다.
실패 조건: 없음
```

## 5. 초기화

```text
people 배열을 오름차순으로 정렬한다.
front_index = 0
back_index = people.length - 1
count = 0
```

## 6. 탐색 공간 및 복잡도

```text
입력 크기 n: people.length
정렬 비용: O(n log n)
투 포인터 탐색: O(n)
전체 시간 복잡도: O(n log n)
추가 공간 복잡도: O(log n) - 정렬 호출 스택 기준
제한 안에서 가능한가: 가능
```

각 사람은 `front_index` 또는 `back_index`에 의해 한 번만 처리되므로 정렬 이후 탐색은 `O(n)`이다.

## 7. 손으로 실행해보기

```text
테스트 입력: [70, 50, 80, 50], limit = 100
정렬 후: [50, 50, 70, 80]
front_index = 0, back_index = 3, count = 0

1회차:
50 + 80 > 100
80은 혼자 탑승
back_index = 2, count = 1

2회차:
50 + 70 > 100
70은 혼자 탑승
back_index = 1, count = 2

3회차:
50 + 50 <= 100
두 사람이 함께 탑승
front_index = 1, back_index = 0, count = 3

front_index > back_index이므로 종료
반환값: 3
```

## 막힌 부분

처음에는 최솟값과 최댓값이 모두 필요하다고 생각해 같은 객체를 최소·최대 우선순위 큐 두 개에 넣고 `rescue` 상태로 동기화했다.
시간 복잡도는 `O(n log n)`이었지만 두 우선순위 큐를 사용한 코드는 시간 초과가 발생했고, 한 우선순위 큐와 투 포인터 코드는 통과했다.

## 풀이 후 배운 점

- 다음 문제에서 가장 먼저 확인할 한 가지: 입력이 고정되어 있고 정렬한 양 끝을 한 번씩 소비한다면 PQ보다 투 포인터로 상태를 줄일 수 있는지 확인한다.
- 다시 풀 때 유지할 모델: 가장 무거운 사람을 항상 처리하고, 가장 가벼운 사람과 함께 탈 수 있을 때만 앞 인덱스도 이동한다.

처음에는 익숙한 PQ를 먼저 선택하고 자료구조를 다시 검토하지 않았다.
다음부터 고정된 입력에서 양 끝값을 반복해서 소비한다면 PQ를 구현하기 전에 정렬과 투 포인터를 먼저 검토한다.
