# 발굴된 동전의 금액 해설

## 문제 요약

동전 $M$개를 각각 최대 한 번씩만 써서 만들 수 있는 $1$ 이상 $S$ 이하의 금액의 개수와 합을 구한다.

## 관찰

부분집합이 $2^{100}$개라 나열은 불가능하다. 앞 문제와 마찬가지로 "만들 수 있는가"만 알면 되므로 상태는 금액 하나로 충분하다. 문제는 **같은 동전을 두 번 쓰지 않게 막는 일**이다.

$dp[x]$를 순서대로 갱신하다 보면, 동전 $v$를 처리하는 도중 $dp[x-v]$가 이미 이번 동전으로 갱신된 값일 수 있다. 그러면 $x$는 $v$를 두 번 쓴 결과가 된다.

핵심 관찰은 이렇다. $x$를 **큰 쪽부터** 훑으면 $dp[x-v]$는 아직 이번 동전이 손대지 않은 자리다. 즉 항상 "이 동전을 쓰지 않은 상태"를 참조하게 되어 각 동전이 최대 한 번만 쓰인다. 순회 방향 하나로 무제한 사용과 한 번 사용이 갈린다.

## 풀이

```java
dp[0] = true;
for (int i = 0; i < m; i++) {
    if (v[i] > s) continue;
    for (int x = s; x >= v[i]; x--)   // 역방향: 이번 동전을 두 번 쓰지 않기 위해
        if (dp[x - v[i]]) dp[x] = true;
}
```

공개 샘플($v = 2, 5, 5, 11$, $S = 12$)을 따라가 보자.

| 처리한 동전 | 새로 켜지는 금액 |
|---|---|
| $2$ | $2$ |
| $5$ (첫 번째) | $5, 7$ |
| $5$ (두 번째) | $10, 12$ |
| $11$ | $11$ |

액면가 $5$짜리가 두 개라서 $10$과 $12$가 만들어진다. 액면가가 같아도 서로 다른 동전이므로 각각 한 번씩 처리해야 한다는 점이 그대로 드러난다. 결과는 $2,5,7,10,11,12$의 $6$가지, 합 $47$.

전체 자바 코드는 `java/B2-Solution.java` 참고.

## 복잡도

- 시간: $O(M \cdot S) = 10^7$.
- 공간: $O(S)$.

## 구현 노트

- 액면가가 같은 동전을 묶어서 "한 종류를 여러 번"으로 처리하고 싶어질 수 있는데, 그건 이 세트의 마지막 문제(개수 제한 배낭)에서 다루는 이야기다. 여기서는 그냥 각각 한 번씩 돌리는 게 맞고 더 간단하다.
- 합은 `long`. 액면가 $1, 2, 4, \dots, 65536$처럼 $2$의 거듭제곱만 줘도 $1$부터 $10^5$까지 전부 만들어져 합이 $50$억이 된다.
- 검증기는 큰 정수 비트 시프트 대신 역방향 boolean DP를 C++로 구현한 것이다. 순회 방향을 정방향으로 잘못 잡으면 두 답이 갈린다.

## 흔한 실수

- 정방향으로 순회해 같은 동전을 여러 번 사용. 액면가가 하나뿐인 데이터에서는 티가 안 나다가 다른 데이터에서 답이 커진다.
- 액면가가 $S$보다 큰 동전을 거르지 않아 인덱스 예외.
- 합을 `int`로 계산해 오버플로.
- 액면가가 같은 동전들을 중복 제거해서 한 번만 처리. $10 = 5+5$를 놓친다.
