## 내가 이해한 문제

- 초단위로 기록된 주식 가격 prices 배열이 주어진다.

특정 초 에서 가격이 떨어지지 않은 기간은 몇 초인지 기록된 int[]로 리턴한다.


## 상태

- Node 인덱스 그리고 주식의 값(int index, int price) 
- priorityque<Node> pq 주식의 값 순으로 정렬 내림차순으로
- prices 인덱스
- int[] answer 정답 저장용 배열(가격이 떨어지지 않은 기간 저장 용)


## 전이

외부 전이

for(int i =0; i< price.length; i++)	// price 하나씩 돌면서

1. pq에서 현재 가격보다 높은 과거 가격들을 꺼낸다.
2. 꺼낸 가격의 유지 시간을 answer에 저장한다.
3. 현재 인덱스와 가격을 Node로 만들어 pq에 넣는다.

내부 전이
while(!pq.isEmpty()) // pq가 없기 전까지 확인

pq.peek().price > prices[price_index] // 과거 가격보다 현재 가격이 낮아졌다면

else break;		// 아니면 while 탈출

Node node = pq.poll()	// pq 하나 비우고

answer[node.index] = 현재시간(현재 인덱스) -  node.index; // 정답 인덱스에 넣어주기

마지막 전이

모든 가격을 확인한 후 pq가 비어 있지 않다면,
남은 Node를 하나씩 꺼내 마지막 인덱스까지의 시간을 answer에 저장한다.

while(!pq.isEmpty()) // pq가 없기 전까지 확인

Node node = pq.poll()	// pq 하나 비우고

answer[node.index] = 마지막 시간(마지막 인덱스) -  node.index; // 정답 인덱스에 넣어주기
while문 빠저나가기 없에 주고 현재시간만 마지막 시간으로 맞춰줘서 진행 하면 된다.

## 탐색 공간 및 복잡도

가이드:
- 입력의 최대 크기는 얼마인가? 최대길이 100,000
- 반복 한 번에 처리하는 대상은 무엇인가? 현재 가격 또는 pq의 Node 1개
- 대상 하나를 확인할 때 다른 전체 대상을 다시 검사하는가? no, pq.peek()만 확인
- 한 대상이 여러 번 대기열에 들어갈 수 있는가? no
- 외부 반복문은 몇 번 실행되는가? n번
- 내부 while의 poll은 전체적으로 몇 번 실행되는가? 최대 n번
- 반복 한 번의 비용은 얼마인가? peek O(1), add와 poll O(log n)
- 전체 비용은 얼마인가? O(n log n) + O(n)
- 최종 시간 복잡도는 얼마인가? O(n log n)
- 공간 복잡도는 얼마인가? O(n)
- 제한 안에서 실행 가능한가? yes
