# 피로도

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/87946
- 유형: 완전탐색, DFS, 백트래킹
- 작성 시기: 2026년 7월 4주차

## 내가 이해한 문제

- 현재 피로도 `k`가 주어진다.
- 던전을 탐험하면 피로도가 소모된다.
- 각 던전에는 입장하기 위한 최소 필요 피로도와 탐험 후 차감되는 소모 피로도가 있다.
- 각 던전은 한 번만 탐험할 수 있다.
- 탐험 순서에 따라 결과가 달라질 수 있다.
- 고정된 정렬 기준으로 최적해를 보장할 수 없으므로 가능한 탐험 순서를 모두 확인한다.
- 탐험할 수 있는 최대 던전 수를 구한다.

## 처음 작성한 모델링

### 상태

- `Fatigue`: 현재 남은 피로도
- `dcount`: 현재까지 던전에 진입한 횟수
- `visited`: 탐색한 던전 저장

### 전이

- 던전에 진입하면 현재 남은 피로도에서 소모 피로도를 뺀다.
- 던전 진입 횟수를 1 증가시킨다.
- 최소 필요 피로도가 현재 남은 피로도보다 크면 해당 던전은 건너뛴다.
- 이미 방문한 던전이면 건너뛴다.

### 제약

- 현재 피로도가 던전의 최소 필요 피로도 이상이어야 한다.
- 이미 방문한 던전은 다시 방문할 수 없다.

### 목표

- 탐험할 수 있는 던전 수의 최댓값을 구한다.

### 처음 잡은 풀이 방향

- 소모 피로도를 기준으로 정렬하려고 했다.
- DFS 함수를 만든다.
- 현재 탐험 횟수와 남은 피로도를 재귀 상태로 전달한다.
- 재귀에 진입할 때마다 최대 탐험 횟수를 갱신한다.
- 모든 던전을 순회하며 방문 여부와 최소 필요 피로도를 확인한다.
- 방문 가능한 던전을 방문 처리한 뒤 다음 DFS로 진입한다.
- 재귀가 끝나면 방문 상태를 복구하고 다른 순서를 탐색한다.

## 피드백 반영 모델링

### 상태

- `fatigue`: 현재 남은 피로도
- `count`: 현재 탐색 경로에서 탐험한 던전 수
- `visited[i]`: 현재 탐색 경로에서 `i`번 던전을 이미 선택했는지

`count`는 현재 경로의 상태이고, `answer`는 모든 경로에서 얻은 최댓값을 저장하는 정답 누적 변수다.

### 전이

현재 상태에서 아직 방문하지 않았고 입장할 수 있는 던전 `i`를 하나 선택한다.

```text
(fatigue, count, visited)
    → (fatigue - dungeons[i][1], count + 1, visited에 i 추가)
```

구현 순서는 다음과 같다.

1. `visited[i] = true`로 변경한다.
2. 소모 피로도를 차감한 값과 `count + 1`을 다음 DFS에 전달한다.
3. 재귀가 끝나면 `visited[i] = false`로 복구한다.

### 제약

- `visited[i] == false`인 던전만 선택할 수 있다.
- `fatigue >= dungeons[i][0]`일 때만 던전에 입장할 수 있다.
- 각 던전은 한 번만 탐험할 수 있다.

### 목표

모든 DFS 상태에서 현재 탐험 횟수와 기존 최댓값을 비교한다.

```java
answer = Math.max(answer, count);
```

가능한 탐험 순서를 모두 확인한 뒤 `answer`를 반환한다.

### 풀이 방향

- 던전의 개수가 최대 8개이므로 가능한 탐험 순서를 DFS로 완전탐색한다.
- 다음 던전이 고정되어 있지 않으므로 각 상태에서 모든 던전을 다음 후보로 확인한다.
- 방문 배열로 현재 경로에서 선택한 던전을 관리한다.
- 재귀 호출 후 방문 상태를 복구하는 백트래킹을 사용한다.
- 정렬은 사용하지 않는다. 탐험 순서 자체가 탐색해야 할 선택지이기 때문이다.

## 막힌 부분

- 2차원 배열 정렬 방법을 잊어버렸다.
- 처음에는 던전을 반복해서 돌 수 있는 문제로 잘못 읽었다.
- 정렬을 통해 하나의 순서를 정하면 된다고 생각했다.
- 처음에는 `visited`를 재귀 호출들이 공유할 필드로 두는 방법을 생각하지 못했다.

## 이번 문제에서 배운 점

### 정렬과 완전탐색의 차이

```text
정렬
→ 하나의 순서를 결정한다.

완전탐색
→ 순서 자체가 선택지일 때 가능한 순서를 확인한다.
```

### `visited`의 의미

이 문제의 `visited`는 전체 탐색에서 영구적으로 방문한 던전을 표시하는 배열이 아니다. 현재 DFS 경로에서 이미 선택한 던전을 나타내므로, 재귀 호출이 끝나면 반드시 복구해야 한다.

### 필드와 매개변수

- 재귀 호출마다 달라지는 `fatigue`, `count`는 매개변수로 전달한다.
- 모든 재귀 호출이 공통으로 참고하는 `dungeons`, `visited`, `answer`는 필드로 둘 수 있다.
- `visited`를 매개변수로 전달하는 것도 가능하지만 같은 배열을 공유한다면 여전히 백트래킹 복구가 필요하다.

### 값 복구

- `fatigue`는 계산한 새 값을 재귀 함수에 전달하므로 현재 호출의 값은 변하지 않는다.
- `visited`는 공유 배열을 직접 변경하므로 재귀 호출 후 원래 값으로 복구해야 한다.
