## 내가 이해한 문제

가장 낮은 두개의 맵지 않은 음식을 섞는다
가장 덜매운거 + 2번째 덜 매운거 * 2

음식에서 가장 덜 매운 음식이 K 보다 크면 통과

크지 못하면 불통과

K보다 클때까지 반복하며

실패하면 -1 반환

## 상태

- count 음식 합친 회수
- priotyque pq 스코빌 지수 순으로 나열된 음식 오름차순 

## 전이

pq에서
가장 스코빌 지수가 작은 음식 2개 뺴서
가장 덜매운거 + 2번째 덜 매운거 * 2
해주고 다시 pq에 삽입


## 제약

pq.peek() >= k 면 count return

pq.size() < 2 인데 k 이상을 충족하지 못했다면 return -1




## 후보별 초기화

여러후보가 있는건 아니라서
pq 초기화
count 초기화
scoville의 모든 값을 pq에 삽입

## 목표

가진 음식의 스코빌 최소 값이 K보다 클 떄 까지 진행 한다.

모든 음식의 스코빌 지수를 K 이상으로 만드는 데 필요한 최소 혼합 횟수를 반환한다.
불가능하다면 -1을 반환한다.

## 탐색 공간 및 복잡도

가이드:
- 입력의 최대 크기는 얼마인가? 최대길이 1000000
- 반복 한 번에 처리하는 대상은 무엇인가? 1 nlogn(pq 삽입)
- 대상 하나를 확인할 때 다른 전체 대상을 다시 검사하는가?  no
- 한 대상이 여러 번 대기열에 들어갈 수 있는가? no
- 반복문은 최악의 경우 몇 번 실행되는가? n-1번
- 반복 한 번의 검사 비용은 얼마인가? O(log n)
- `전체 반복 횟수 × 한 번의 검사 비용`은 얼마인가? nlog n + o(n)
- 제한 안에서 실행 가능한가? yes
