# 25. 두 상자의 카드 합의 K번째 수

## 문제 분석
카드 `N`장을 가진 상자 `A`와 카드 `M`장을 가진 상자 `B`에서 카드를 각각 한 장씩 골라 두수의 합을 만들 수 있습니다.
따라서 만들 수 있는 조합의 수는 $N \times M$입니다.

만들 수 있는 모든 조합을 오름차순으로 나열했을 때, `K`번째로 작은 값이 무엇인지 구해야 합니다.
그러나, 이 문장 그대로 모든 조합을 구한 뒤 정렬하고 그 중 `K`번째 값을 찾는 방식으로 설계하게 되면 다음 조건이 발목을 잡습니다.

**`N`과 `M` 모두 최대 `100,000`입니다. 즉, $N \times M = 10,000,000,000$(백억)입니다.**
이에 의해 두 가지 복잡도 관련 문제를 직면하게 됩니다.
- **1. $N \times M$ 개의 조합을 직접 다 구할 것인가?**
- **2. 설령 $N \times M$ 개의 조합을 다 구했다고 쳐도, 저 크기의 메모리를 보관할 수 있는가?**

당연히 이렇게 풀라고 주어진 상황이 아니겠죠.
그래서 위의 문장 자체를 해석하고 재구성할 필요가 있습니다.
이에 대합 해답이 **23번 문제 : 카드 합 세기**에 있다고 생각했습니다.

## 문제의 재구성
해당 문제에서는 카드 `N`장에서 임의의 서로 다른 두 장을 골라 두 수를 합쳤을 때의 합이 `X` 이하인 조합의 수를 구해야 합니다.
반대로, 현 문제에서는 **만들어야 할 조합의 수가 이미 주어져 있고 그 중 가장 큰 수가 무엇인가**를 구해야 하는 상황입니다.
이 내용들을 적절히 재배치하면 현 문제의 요구사항을 다음과 같이 재구성하였습니다.

> **두 숫자의 합이 X 이하인 카드 조합의 수가 K장 이상이라고 할 때, 이를 충족하는 X의 최소값을 구하라.**

이렇게 문제를 재구성하면 해야 할 일이 명확해집니다. 
1. 임의의 `X`값을 던지고, 
2. 두 수의 합이 `X` 이하인 조합의 수를 카운트한 뒤, 
3. 그 결과에 따라 범위를 좁혀나가면 됩니다.

## 설계 및 구현
### 1. 초기 X값 범위 제한
```java
long min = A[0] + B[0], max = A[N-1] + B[M-1];
```
굳이 볼 필요 없는 값을 `X`에 대입하지 않기 위해 만들 수 있는 조합 중 가장 작은 값과 가장 큰 값으로 범위를 제한하려 했습니다.
두 상자의 카드들을 각각 오름차순으로 정렬한 뒤
최소값은 두 상자의 `0`번째 카드의 합으로, 최대값은 각 상자의 `N-1`번째 카드와 `M-1`번째 카드의 합으로 초기화합니다.

### 2. 매개변수 탐색
```java
while(min <= max) {
    long mid = min + (max-min)/2;
    
    long cnt = getCombiCnt(mid);
    if(cnt >= k) max = mid - 1;
    else min = mid + 1;
}
```
두 수 사이의 미지수를 알아내는 가장 빠른 방법은 일단 반으로 나누고 결과를 본 뒤 필요 없는 반을 버리는 것입니다.
따라서 현재 해가 될 가능성이 있는 범위의 정중앙에 있는 값을 임의의 `X`값으로 던져 두 수의 합이 `X` 이하인 조합의 수를 카운트합니다.

- 만약 조합의 수가 `K` 이상이면 중앙값 mid로는 `K`번째 값 확인이 가능하니 더 작은 값을 테스트하기 위해 최대값을 `mid - 1`로 내립니다.
- 만약 조합의 수가 `K` 미만이면 중앙값 `K`번째 값이 무엇인지 알 수 없으므로 더 큰 값을 테스트하기 위해 최소값을 `mid + 1`로 올립니다.

### 3. 투 포인터
```java
static long getCombiCnt(long X) {
    // left는 상자 A의 첫 카드, right는 상자 B의 마지막 카드
    int left = 0, right = M-1;
    long cnt = 0;

    // 두 포인터 중 어느 한 쪽이 배열 범위 밖을 빠져나가면 즉시 루프 종료
    while(left < N && right >= 0) {
        long sum = A[left] + B[right];
        if(sum > X) right--;
        else {
            cnt += right+1;
            left++;
        }
    }

    return cnt;
}
```
임의의 `X`값이 주어졌으므로 두 수의 합이 `X` 이하인 조합의 수를 카운트해야 합니다.
각 조합의 값은 중요하지 않고 오직 **조건을 충족하는 조합의 수만 요구**하므로 투 포인터를 이용해 불필요한 카운트를 줄이고 한꺼번에 개수를 파악하고자 했습니다.

두 상자에 각각 반대 방향으로 이동하는 두 포인터를 적용합니다.
- **상자 A :** `0`부터 `N-1`로 이동하는 순방향 포인터
- **상자 B :** `M-1`부터 `0`으로 이동하는 역방향 포인터

상자 `A`의 최소값 카드와 상자 `B`의 최대값 카드의 합이 `X` 이하라면
상자 `B`의 나머지 카드들도 조건을 충족한다. 

-> `right` 크기만큼 카운트하고 상자 `A`의 카드를 더 높은 값으로 올려본다.

상자 `A`의 최소값 카드와 상자 `B`의 최대값 카드의 합이 `X` 초과라면
상자 `A`의 나머지 카드들도 조건을 충족하지 않는다.

-> 상자 `B`의 카드는 더 낮은 값으로 내려본다.

## 복잡도
- **정렬:** 두 상자를 각각 정렬하므로 $O(N \log N + M \log M)$
- **매개변수 탐색:** 합의 범위(최대 $3 \times 10^9$)를 반씩 좁히므로 약 32회, $O(\log(\text{합의 범위}))$
- **투 포인터:** 두 포인터가 각자 한 방향으로만 이동하므로 호출당 $O(N + M)$

종합하면 탐색 항이 지배적이라 전체 시간 복잡도는 $O((N + M)\log(\text{합의 범위}))$, 공간 복잡도는 $O(N + M)$입니다.
