# 유물 창고의 금액 해설

## 문제 요약

$i$번째 종류의 동전을 $0$개 이상 $c_i$개 이하로 쓸 수 있을 때, 만들 수 있는 $1$ 이상 $S$ 이하 금액의 개수와 합을 구한다. $c_i$는 최대 $10^9$이다.

## 관찰

**관찰 1 — 개수는 잘라도 된다.** 액면가 $v$짜리를 $\lfloor S/v \rfloor$개보다 많이 쓰면 금액이 이미 $S$를 넘는다. 그러니 실제 사용 가능 개수는 $k = \min(c_i, \lfloor S/v_i \rfloor)$로 줄여도 답이 변하지 않는다. $10^9$이라는 큰 수가 $10^5$ 이하로 내려온다.

**관찰 2 — 그래도 낱개로 펼치면 안 된다.** $k$가 여전히 $10^5$까지 갈 수 있고 종류가 $100$개면 총 $10^7$개의 "한 번짜리 동전"이 생긴다. 각각에 대해 $O(S)$ DP를 돌리면 $10^{12}$번이다.

**관찰 3 — 개수를 이진법으로 묶는다.** $k$개를 $1, 2, 4, \dots$ 크기의 묶음과 나머지 하나로 쪼개면, 이 묶음들의 부분집합 합으로 $0$부터 $k$까지의 모든 개수를 정확히 한 번씩 표현할 수 있다. 예를 들어 $k = 11$은 $1, 2, 4, 4$로 쪼개진다($1+2+4+4=11$이고 $0 \sim 11$이 전부 표현된다). 묶음은 $\lceil \log_2(k+1) \rceil$개뿐이고, **각 묶음은 한 번만 쓸 수 있는 동전**이므로 B2에서 쓴 역방향 0/1 배낭을 그대로 적용하면 된다.

즉 이 문제는 "개수 상한을 $\lfloor S/v \rfloor$로 자르는 감각"(B3에서 다룬, 무제한이나 다름없는 상황을 알아채는 눈)과 "역방향 0/1 배낭"(B2)을 이어 붙인 것이다.

## 풀이

```java
long k = Math.min(c, s / v);          // 관찰 1
long step = 1;
while (step <= k) {                    // 관찰 3: 1, 2, 4, ... 묶음
    int shift = (int) (v * step);
    for (int x = s; x >= shift; x--)   // 관찰 2: 묶음 하나 = 0/1 배낭 한 번
        if (dp[x - shift]) dp[x] = true;
    k -= step;
    step <<= 1;
}
if (k > 0) { /* 남은 나머지 묶음도 같은 방식으로 한 번 */ }
```

공개 샘플($v=2$가 $3$개, $v=5$가 $1$개, $S=12$)에서 첫 종류는 $k = \min(3, 6) = 3$이라 묶음이 $\{1, 2\}$로 쪼개진다. 무게 $2$짜리 한 번, 무게 $4$짜리 한 번을 0/1로 처리하면 $\{0,2,4,6\}$이 켜진다. $8$은 켜지지 않는다 — 동전이 세 개뿐이기 때문이다. 이어서 $v=5$를 $k=1$로 처리하면 $5,7,9,11$이 추가된다. 답은 $7$가지, 합 $44$.

전체 자바 코드는 `java/B1-Solution.java` 참고.

## 복잡도

- 시간: $O\!\left(S \sum_i \log(\min(c_i, S/v_i))\right)$. 최악은 $100 \times 17$개 묶음 $\times\ 10^5 = 1.7 \times 10^8$ 단순 연산이라 자바에서 1초 이내다.
- 공간: $O(S)$ boolean 배열 하나.

## 구현 노트

- $v \cdot step$이 $S$를 넘지 않는 것은 $step \le k \le S/v$에서 보장된다. 그래도 곱은 `long`으로 계산한 뒤 인덱스로 쓸 때만 캐스팅하는 편이 안전하다.
- 각 묶음마다 반드시 **역방향** 순회를 유지한다. 묶음 하나를 두 번 쓰면 개수 제한이 깨진다.
- 이진 분할 대신 $O(M \cdot S)$짜리 다른 풀이도 있다. 금액마다 "현재 동전이 몇 개 남았는지"를 기록하며 정방향으로 훑는 방법인데, 이 문제의 검증기가 바로 그 구현이다. 두 풀이는 원리가 완전히 달라서 이진 분할의 나머지 묶음 처리를 빠뜨리면 즉시 불일치가 난다.
- 액면가가 $S$보다 큰 종류는 $s/v = 0$이 되어 묶음이 하나도 생기지 않는다. 그래도 인덱스 안전을 위해 미리 걸러 두는 게 낫다.

## 흔한 실수

- 개수를 자르지 않고 $c_i$를 그대로 이진 분할. $c_i = 10^9$이면 묶음이 $30$개가 되어 불필요하게 느려지고, $v \cdot step$이 `int` 범위를 넘어 음수 인덱스가 될 수 있다.
- 이진 분할의 마지막 나머지($k$가 $2$의 거듭제곱 합으로 딱 떨어지지 않을 때 남는 부분)를 처리하지 않기. $k = 3$처럼 작은 값에서 바로 틀린다.
- 개수 제한을 무시하고 무제한 배낭(정방향)으로 풀기. 액면가가 작고 개수가 $1{,}2{,}3$개뿐인 데이터에서 답이 크게 부풀어 오른다.
- 합을 `int`로 계산해 오버플로.
