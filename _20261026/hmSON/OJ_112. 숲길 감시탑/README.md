# OJ_112. 숲길 감시탑

트리 구조의 숲길에서 모든 쉼터가 최소 하나의 감시탑에게 감시받도록 할 때의 최소 비용을 구해야 함

감시탑은 자기 자신과 인접한 쉼터를 감시하므로, **하위 쉼터뿐 아니라 상위 쉼터도 감시 대상**이 됨<br>
이 양방향성이 상태 설계를 까다롭게 만드는 지점


## 1. 2상태 설계의 실패
처음에는 각 쉼터를 "설치 / 미설치" 두 상태로만 나누어 접근했으나 오답

> **미설치 상태 안에 서로 다른 두 가지가 섞여 있었기 때문**

- 하위 쉼터가 감시탑을 세워 **이미 감시받고 있는** 미설치 상태
- 아직 **누구에게도 감시받지 못한** 미설치 상태

두 상태는 상위 쉼터 입장에서 전혀 다른 의미를 가짐

전자는 자기 자리에 탑이 없으므로 **상위 쉼터를 감시하지 못함**<br>
후자는 **상위 쉼터가 반드시 감시탑을 세워야 함**을 강제함

이를 구분하지 않으면 "하위 쉼터가 자기 하위에게 감시받고 있어서, 상위 쉼터는 따로 해결해야 하는" 경우를 놓쳐 더 저렴한 조합을 선택하지 못함


## 2. 상태 정의 - 3상태 트리 DP
> - `built[v]` : v에 감시탑을 설치한 경우의 최소 비용
> - `underSurveil[v]` : v에 설치하지 않았으나 하위 쉼터로부터 감시받는 경우
> - `withoutSurveil[v]` : v에 설치하지 않았고 아직 감시받지 못한 경우 (상위 쉼터가 반드시 설치해야 함)

### 2-1. 리프 쉼터의 초기 상태
- `built` : 자기 설치 비용 그대로
- `underSurveil` : 감시탑을 세울 하위 쉼터가 없으므로 **불가능(INF)**
- `withoutSurveil` : 아무것도 하지 않으므로 **0**

`underSurveil`을 INF로 초기화해 두면, 하위 쉼터를 한 번도 처리하지 않은 쉼터가 자연히 리프로 판별됨


## 3. 상태별 전이

### 3-1. built - 하위 쉼터 자유 선택
cur에 감시탑이 서면 모든 하위 쉼터가 감시받으므로, 하위 쉼터는 세 상태 중 아무거나 골라도 됨

```java
built[cur] += min3(built[next], underSurveil[next], withoutSurveil[next]);
```

리프 하위 쉼터는 `withoutSurveil`이 0이므로 추가 비용 없이 처리됨

### 3-2. underSurveil - 최소 하나는 설치 의무
cur이 하위 쉼터에게 감시받으려면 **하위 쉼터 중 최소 하나가 감시탑을 설치**해야 함

기본적으로 각 하위 쉼터의 `min(built, underSurveil)`을 누적하되, 그 결과 아무도 설치하지 않았다면 한 곳을 강제로 설치시켜야 함

```java
long curDiff = built[next] - underSurveil[next];
if(curDiff < minDiff) minDiff = curDiff;
...
underSurveilSum += (minDiff <= 0 ? 0 : minDiff);
```

이 비용차가 **음수라면 어차피 설치하는 쪽이 이득**이므로 설치 의무가 이미 충족된 상태<br>
모든 하위 쉼터의 비용차가 양수라면, 그중 가장 작은 값을 추가 비용으로 더해 한 곳을 강제 설치

### 3-3. withoutSurveil - 하위 쉼터가 스스로 해결
cur이 감시받지 못한 상태라면, 하위 쉼터들은 cur의 도움 없이 각자 감시받아야 함

```java
withoutSurveil[cur] += underSurveil[next];
```

단, 하위 쉼터 중 리프가 있으면 그 리프는 cur이 세워주지 않는 한 감시받을 방법이 없으므로 **불가능(INF)**


## 4. 루트 처리
루트는 상위 쉼터가 없으므로 `withoutSurveil` 상태를 선택할 수 없음

```java
System.out.println(Math.min(built[0], underSurveil[0]));
```


## 5. 구현 주의점
### 5-1. 재귀 대신 명시적 스택
쉼터가 최대 100,000개이고 한쪽으로 치우친 트리가 주어질 수 있어 재귀 DFS는 스택 오버플로 위험<br>
한 노드에 두 번 접근하는 구조(진입 시점에 하위 쉼터를 올리고, 탈출 시점에 값을 확정)로 후위 순회를 구현

### 5-2. 하위 쉼터 판별
무방향 인접 리스트이므로 `visited`만으로는 탈출 시점에 하위 쉼터를 가려낼 수 없음<br>
진입 시점에 기록해 둔 `parent` 배열을 이용해 상위 쉼터 하나만 건너뛰면 나머지가 모두 하위 쉼터

### 5-3. INF의 누적
`withoutSurveil`에 값을 누적하는 과정에서 INF를 초과할 수 있으므로, 매번 INF로 되돌려 불가능 상태를 유지해야 함


## 6. 복잡도
- 각 쉼터는 스택에 정확히 두 번 등장 : $O(N)$
- 각 쉼터에서 하위 쉼터를 한 번씩 순회 : 전체 간선 수에 비례하여 $O(N)$

전체 시간 복잡도는 $O(N)$, 공간 복잡도는 DP 배열과 인접 리스트로 $O(N)$
