# 검사창에 잡힌 최저 높이 해설

## 문제 요약

길이 $N$인 수열에서 연속한 $K$개짜리 구간을 왼쪽부터 한 칸씩 옮겨가며 각 구간의 최솟값을 구하고, 그 최솟값 $N-K+1$개를 모두 더한 값을 출력한다.

## 관찰

구간마다 따로 최솟값을 구하면 한 구간에 $K$번 비교하므로 $(N-K+1) \times K$번이다. $N = 300{,}000$, $K = 150{,}000$이면 약 $2.25 \times 10^{10}$번이라 어떤 언어로도 못 버틴다.

검사창이 한 칸 움직일 때 실제로 바뀌는 건 두 개뿐이다. 왼쪽 끝 하나가 빠지고 오른쪽 끝 하나가 들어온다. 나머지 $K-1$개는 그대로인데 매번 처음부터 다시 훑는 게 낭비다. 그러니 창이 움직일 때 **바뀐 부분만 반영해서 최솟값을 유지**하면 된다.

여기서 핵심이 되는 관찰이 하나 있다. 어떤 두 부품 $i < j$에 대해 $a_i \ge a_j$라면, $i$는 앞으로 **영원히 최솟값이 될 수 없다**. $i$가 창에 들어 있으면 그보다 오른쪽인 $j$도 반드시 창에 들어 있고(창은 오른쪽으로만 움직이므로 $i$가 살아 있는 동안 $j$는 이미 들어왔다), $a_j$가 $a_i$ 이하이기 때문이다. 그러면 $i$는 그 자리에서 버려도 답이 달라지지 않는다.

버릴 것을 다 버리고 남은 후보들만 왼쪽부터 늘어놓으면 값이 **증가하는 순서**가 된다. 남은 후보의 맨 앞이 곧 현재 창의 최솟값이다.

## 풀이

인덱스를 담는 덱(양쪽 끝에서 넣고 뺄 수 있는 자료구조)을 하나 두고, 그 안의 값이 항상 증가 순서를 유지하도록 관리한다. $i$를 $0$부터 $N-1$까지 늘려가며 세 가지를 한다.

1. **뒤에서 버리기**: 덱 뒤쪽 인덱스의 값이 $a_i$ **이상**이면 뺀다. 위 관찰에 따라 그 인덱스는 다시 최솟값이 될 수 없다. 그리고 $i$를 뒤에 넣는다.
2. **앞에서 버리기**: 덱 맨 앞 인덱스가 $i - K$ 이하면(= 창 밖으로 나갔으면) 뺀다. 창이 한 칸만 움직였으므로 나가는 인덱스는 많아야 하나라서 `while`이 아니라 `if`로 충분하다.
3. **더하기**: 오른쪽 끝이 $i$인 창은 $i \ge K-1$일 때 완성된다. 그때 덱 맨 앞의 값을 답에 더한다.

```java
while (head < tail && a[dq[tail - 1]] >= v) tail--;  // 등호 포함: 같은 값이면 오래된 쪽을 버린다
dq[tail++] = i;
if (dq[head] <= i - k) head++;                       // 창 밖으로 나간 인덱스 제거
if (i >= k - 1) total += a[dq[head]];                // 맨 앞이 곧 이 창의 최솟값
```

공개 샘플($a = 3, 1, 4, 1, 5, 9, 2, 6$, $K = 3$)로 덱의 변화를 따라가 보자. 덱은 값으로 표시했다.

| $i$ | $a_i$ | 뒤에서 버린 값 | 앞에서 버린 값 | 처리 후 덱 | 답에 더한 값 | 누적 |
|---|---|---|---|---|---|---|
| 1 | 3 | - | - | [3] | - | 0 |
| 2 | 1 | 3 | - | [1] | - | 0 |
| 3 | 4 | - | - | [1, 4] | 1 | 1 |
| 4 | 1 | 4, 1 | - | [1] | 1 | 2 |
| 5 | 5 | - | - | [1, 5] | 1 | 3 |
| 6 | 9 | - | - | [1, 5, 9] | 1 | 4 |
| 7 | 2 | 9, 5 | 1 | [2] | 2 | 6 |
| 8 | 6 | - | - | [2, 6] | 2 | 8 |

$i = 4$에서 값 $1$을 버린 게 눈에 띈다. 같은 값 $1$이 새로 들어왔으니 더 오래된 쪽은 먼저 창 밖으로 나갈 운명이라 남겨둘 이유가 없다. $i = 7$에서는 뒤에서 $9, 5$를 버린 직후 맨 앞의 $1$이 창 밖($3$번 부품)으로 나가 앞에서도 하나 빠진다.

전체 자바 코드는 `java/B2-Solution.java` 참고.

## 복잡도

시간: $O(N)$ — 각 인덱스는 덱에 정확히 한 번 들어가고 많아야 한 번 나온다. 안쪽 `while`이 도는 총횟수는 전체를 통틀어 $N$번을 넘지 않는다.

공간: $O(N)$ — 높이 배열과 덱. 덱에 동시에 들어 있는 인덱스는 많아야 $K$개다.

## 구현 노트

- **합은 `long`이다.** 최솟값 하나는 $10^9$ 규모지만 기록이 최대 $300{,}000$개라 합의 절댓값이 $3 \times 10^{14}$까지 간다. `int`로 받으면 오버플로로 엉뚱한 값이 나오는데, 작은 예제에서는 멀쩡히 통과해서 알아채기 어렵다.
- **뒤에서 버릴 때 등호를 포함한다.** `>` 로 쓰면 같은 값이 인접할 때 덱에 중복이 쌓인다. 답 자체는 여전히 맞지만 덱이 불필요하게 길어진다. 값이 $-3 \sim 3$ 범위인 생성 케이스가 이 상황을 대량으로 만든다.
- **덱에는 값이 아니라 인덱스를 넣는다.** 값만 넣으면 창 밖으로 나갔는지 판단할 수 없다.
- **앞에서 버리는 조건의 부등호**를 헷갈리기 쉽다. 오른쪽 끝이 $i$인 창의 범위는 $[i-K+1,\ i]$이므로 맨 앞 인덱스가 $i-K$ **이하**면 버린다.
- **덱을 배열로 구현할 때 크기는 $N$.** 인덱스가 한 번씩만 들어가므로 $K$가 아니라 $N$으로 잡아야 안전하다.
- 이 문제의 검증기는 덱을 전혀 쓰지 않고 희소 배열로 구간 최솟값을 조회한다. 덱의 등호 처리나 창 이탈 조건을 잘못 잡으면 답이 미묘하게 어긋나는데, 완전히 다른 방식으로 같은 값을 계산해 그런 어긋남을 잡아낸다.

## 흔한 실수

- 창마다 `min`을 다시 구하는 $O(NK)$ 풀이. $K$가 작은 케이스에서는 통과하는 것처럼 보여서 $K = 150{,}000$짜리 케이스에서 처음 터진다.
- 누적합을 `int`로 선언해 생기는 오버플로. 높이가 전부 $10^9$이거나 전부 $-10^9$인 케이스가 이걸 겨냥한다.
- $K = N$일 때 기록이 $1$개, $K = 1$일 때 기록이 $N$개라는 걸 놓치고 반복 범위를 잘못 잡는 경우. 특히 $N = K = 1$에서 답이 $a_1$인지 확인해 보면 좋다.
- 창이 아직 완성되지 않은 $i < K-1$ 구간에서도 답을 더해버리는 실수.
- 덱이 비었는지 확인하지 않고 `a[dq[tail - 1]]`에 접근하는 실수. 내림차순 입력에서는 새 값이 들어올 때마다 덱이 통째로 비므로 곧바로 예외가 난다.
