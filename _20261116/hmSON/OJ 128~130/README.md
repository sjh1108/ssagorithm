# OJ 128 ~ 130

최장 증가 부분 수열(LIS)을 다루는 세 문제<br>
**2차원 조건을 1차원으로 내리는 정렬**과 **`O(N log N)` 이분 탐색 LIS** 가 기반이며, 마지막엔 길이를 넘어 **어떤 원소가 최장 수열에 쓰일 수 있는가**까지 다룸


## 128. 나무 인형 포개기

**요구사항** : 너비와 높이가 모두 엄격히 작아야 포갤 수 있을 때, 포갤 수 있는 최대 개수

### 조건 하나를 정렬로 없애기
고르는 순서가 자유로우므로 **너비 오름차순 정렬**하면 너비 증가는 순서로 보장되고, 높이 하나만 남음

### 같은 너비의 함정
너비가 같은 인형은 서로 포갤 수 없는데, 높이만 보는 LIS는 이를 모르고 이어 붙일 수 있음

> **너비가 같으면 높이 내림차순으로 정렬**해, 같은 너비끼리는 높이가 감소하여 이어질 수 없게 만듦

같은 너비 중 하나만 고르는 방식은 안 됨. 높은 쪽은 앞을 많이 담고 낮은 쪽은 뒤에 잘 들어가서 어느 쪽이 최적인지 미리 정할 수 없음

### 두 가지 풀이
- **DP `O(N²)`** : 두 조건을 직접 비교하므로 같은 너비의 정렬 방향은 무관. `N ≤ 3,000` 이라 충분
- **이분 탐색 `O(N log N)`** : `lis[len]` = 길이 `len+1` 인 수열의 끝값 최솟값. lower bound 위치에 덮어쓰기


## 129. 진열장의 오름차순 기록

**요구사항** : 각 인형을 마지막으로 고르는 순증가 부분 수열의 최대 길이

### 직전 문제와의 차이
조건은 1차원(키)이지만 **원래 순서를 유지**해야 하므로 정렬 불가<br>
`N ≤ 200,000` 이라 DP는 약 200억 회로 불가능 → 이분 탐색 필수

### 덮어쓰는 위치가 곧 답
lower bound로 찾은 위치 `idx` 는 "이 원소 앞에 이어 붙일 수 있는 최대 길이"<br>
따라서 **`idx + 1` 이 그대로 `f_i`** 이며, 추가 계산 없이 LIS를 한 번 돌리며 바로 출력

`lis` 배열 자체는 실제 수열이 아님. 칸마다 서로 다른 수열의 끝값 정보를 담고 있어 길이만 정확함


## 130. 가장 깊은 포개기에 쓰이는 인형

**요구사항** : 최대 깊이 `L` 과, 깊이 `L` 인 포개기 중 하나 이상에 들어가는 인형 전부

### 양방향 길이
각 인형마다 두 값을 구함
- **asc** : 이 인형을 가장 바깥에 둘 때 안쪽으로 포갤 수 있는 최대 길이 (129의 방식)
- **desc** : 이 인형을 가장 안쪽에 둘 때 바깥쪽으로 포갤 수 있는 최대 길이

> **`asc + desc - 1 == L` 이면 깊이 `L` 인 포개기에 들어감**

자기 자신이 양쪽에서 한 번씩 세어지므로 하나를 뺌. 0-based 위치로 기록하면 `asc + desc == L - 1`
즉, 자기 자신을 기준으로 **안쪽과 바깥쪽에 최대 몇 개의 인형이 존재할 수 있는지** 구하는 것이 이번 문제의 핵심

### 역방향 처리
같은 정렬 배열을 **뒤에서부터** 훑으며 높이가 감소하는 LIS를 구함<br>
높이에 `-1` 을 곱해 넣으면 감소가 증가로 바뀌어 같은 이분 탐색을 그대로 사용 가능

뒤에서 훑으면 같은 너비끼리 높이가 증가하는 순서가 되어, 128의 "같은 너비는 이어지지 않는" 구조가 자연히 유지됨<br>
같은 인형 묶음을 반대로 읽는 것이므로 양방향의 `len` 은 항상 같음

### 원래 번호 보존
정렬로 순서가 섞이므로 `{ 원래 번호, 너비, 높이 }` 로 저장해 결과를 원래 번호 자리에 기록<br>
마지막에 번호 순서대로 훑으면 출력이 자연히 오름차순


## 시리즈 정리

| 조건 | 2차원 | 1차원 + 순서 고정 | 2차원 |
| 구하는 것 | 최대 길이 | 원소별 길이 | 최대 길이 + 관여 원소 |
| 핵심 도구 | 정렬 + LIS | 이분 탐색 LIS | 정렬 + 양방향 LIS |
