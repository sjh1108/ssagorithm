# 45. 검사창에 잡힌 최저 높이


## 문제 분석
`N`개의 부품이 왼쪽부터 한 줄로 놓여있고, 각 부품마다 높이를 입력받습니다. 연속된 부품 `K`개를 한 번에 볼 수 있는 검사창을 통해 **창 내 부품 중 가장 낮은 높이**를 기록합니다. 각 기록의 합을 구하는 것이 이 문제의 목표입니다.

전형적인 슬라이딩 윈도우 문제로 보았으나, 투 포인터를 적용하려 하면 문제가 발생합니다. 
- 기존에 최소값이었던 부품이 윈도우에서 빠질 때, **"그 다음 최소값은 어디에 있는가? 이를 윈도우 내 순차 탐색으로 구할 것인가?"**

검사창의 크기인 `K` 또한 최대 `N`값과 동일하거나 가까운 값으로 주어질 수 있기 때문에 윈도우 순차 탐색은 시간 초과를 발생시킬 수 있습니다. 따라서 투 포인터 대신 **Deque(덱)을 운용하는 슬라이딩 윈도우** 로직이 필요할 것으로 보았습니다. 다음 구상에 따라 이 문제를 해결해야 합니다.

### 1. 덱 내부의 각 원소들은 부품의 순서와 높이를 관리
윈도우(덱) 내부에서 부품의 진입 시점을 알고 있어야 윈도우에서 빠져야 할 부품을 적절한 타이밍에 제거할 수 있습니다. 


### 2. 덱은 높이 오름차순을 유지
덱의 내부를 높이 오름차순으로 유지하면 첫번째 값을 항상 최소값으로 유지하는 동시에 기존 최소값이 윈도우에서 빠지더라도 그 다음으로 작은 값을 바로 확인할 수 있습니다.

또한 윈도우에 새 부품이 들어올 때, 기존 윈도우에 새 부품보다 높이가 크거나 같은 부품을 전부 제거하고 덱의 마지막에 새 부품 정보를 입력하여 오름차순을 유지합니다.


### 3. 각 검사마다 윈도우의 최소값 합산
상기한 대로 덱의 내부를 오름차순으로 유지함으로써 매 턴마다 덱 내 처음 부품의 높이를 합산하여 문제를 해결할 수 있습니다.


## 설계 및 구현


### 1. 상태 정의 : Deque(덱)을 이용한 윈도우 관리
```java
Deque<int[]> deq = new ArrayDeque<>();
st = new StringTokenizer(br.readLine());
for(int i=0; i<k; i++) {
    int val = Integer.parseInt(st.nextToken());
    while(!deq.isEmpty() && deq.peekLast()[1] >= val) deq.removeLast();
    deq.addLast(new int[] {i, val});
}
long total = deq.peekFirst()[1];
```

덱의 각 원소는 `int` 배열로 각 부품의 { 순서(인덱스), 높이 }를 의미합니다.
검사창이 가득 차지 않았을 때에는 검사하지 않으므로, 초기 검사창의 정보를 미리 저장하고 첫 검사 결과를 미리 합산합니다.


### 2. 슬라이딩 윈도우
```java
for(int i=k; i<n; i++) {
    if(deq.peekFirst()[0] + k <= i) deq.removeFirst();

    int val = Integer.parseInt(st.nextToken());
    while(!deq.isEmpty() && deq.peekLast()[1] >= val) deq.removeLast();
    deq.addLast(new int[] {i, val});

    total += deq.peekFirst()[1];
}
```

다음 순서에 따라 매 부품 입력시의 윈도우 현황을 갱신합니다.
1. 현재 최소값(덱의 첫번째 값)이 윈도우에서 빠져야 할 차례라면 -> removeFirst()
2. 새로 검사창에 들어온 부품 높이 확인
3. 현재 윈도우 내에서 새 부품 높이보다 높거나 같은 값들은 필요 없으므로 전부 윈도우에서 제거 -> 큰 값들은 덱의 마지막에 있으므로 removeLast()
4. 새 부품 정보를 덱의 마지막에 추가 -> addLast()
5. 현재 최소값을 `total`에 합산 -> peekFirst()
