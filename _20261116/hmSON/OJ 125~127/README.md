# OJ 125 ~ 127

XOR 비트 연산을 다루는 세 문제<br>
두 수 XOR을 비트 단위로 다루는 이진 트라이를 다룬 이후 이를 이용해 **누적 XOR**에 이진 트라이를 응용하는 형태


## 125. 룬 석판의 공명 구간

**요구사항** : 구간 XOR이 정확히 `K` 인 구간의 수

`N ≤ 5,000` 이라 모든 구간을 직접 확인해도 약 1,250만 회로 충분<br>
현재 위치에서 끝나는 모든 구간의 XOR을 배열에 들고, 원소가 하나 추가될 때마다 전부 갱신

> **핵심** : XOR은 같은 값을 두 번 적용하면 상쇄된다는 성질

이 문제에선 완전 탐색으로 풀었지만, 이 성질이 이후 두 문제의 열쇠가 됨


## 126. 룬 조각 두 개의 최대 공명

**요구사항** : 서로 다른 두 수의 XOR 최댓값

### 직전 문제와의 차이 : 규모
`N ≤ 100,000` 이라 모든 쌍 비교는 약 50억 회로 불가능

### 그리디의 방향
> **상위 비트 하나가 하위 비트 전부보다 크므로, 상위 비트부터 "반대 비트"를 고르는 쪽이 최적**

### 이진 트라이
모든 수를 30비트로 쪼개 상위 비트부터 트라이에 저장<br>
`trie[노드][비트] = 다음 노드` 형태의 2차원 배열로 구현해 객체 생성 없이 처리

조회는 각 비트에서 **반대 비트가 있으면 그쪽, 없으면 같은 쪽**으로 내려가며 XOR을 쌓음<br>
조회 한 번이 30단계로 고정되어 전체 `O(30N)`

**조회 후 삽입** 순서로 진행하면 트라이에 앞선 수만 있어 자기 자신과 짝지어지지 않음


## 127. 문턱을 넘는 공명 구간

**요구사항** : 구간 XOR이 `K` **이상**인 구간의 수

### 125와 126의 결합
구간 XOR은 누적 XOR 두 값으로 표현됨

> `a_l ⊕ … ⊕ a_r = P[r] ⊕ P[l-1]`

상쇄 성질 덕분에 **"구간 XOR" 이 "두 수의 XOR"** 로 바뀌고, 126의 트라이를 그대로 쓸 수 있게 됨<br>
트라이에는 룬 값이 아니라 **누적 XOR 값**을 넣으며, 한 번 넣은 값은 바뀌지 않으므로 트라이를 갱신할 일이 없음

### 직전 문제와의 차이 : 최댓값에서 개수로
126은 최댓값 하나를 찾았지만, 여기선 조건을 만족하는 **개수**를 세야 함<br>
각 노드를 지나간 누적값의 수를 별도 배열로 기록

조회 중 각 비트에서
- 반대 비트로 가면 `K` 이상이 확정될 때 → 그 서브트리 개수를 한 번에 더하고 같은 비트 쪽으로 진행
- 아직 확정되지 않을 때 → 반대 비트 쪽으로 계속 내려감

같은 비트 쪽은 아래를 전부 1로 채워도 `K` 에 못 미치므로 볼 필요가 없음

`P[0] = 0` 과의 쌍(1번부터 시작하는 구간)은 트라이에 넣는 대신 별도로 판정


## 시리즈 정리

| | 125 | 126 | 127 |
|---|---|---|---|
| 대상 | 구간 XOR | 두 수 XOR | 구간 XOR |
| 구하는 것 | `= K` 개수 | 최댓값 | `≥ K` 개수 |
| 핵심 도구 | 완전 탐색 | 이진 트라이 | 누적 XOR + 이진 트라이 |
| 규모 | 5,000 | 100,000 | 200,000 |
