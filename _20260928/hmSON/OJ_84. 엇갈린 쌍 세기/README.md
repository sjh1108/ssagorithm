# OJ_84. 엇갈린 쌍 세기

서로 다른 두 낱장에 대해 왼쪽에 놓인 낱장이 오른쪽에 놓인 낱장보다 클 때, 이 순서쌍을 "**엇갈린 쌍**"이라고 합니다.
엇갈린 쌍의 총 개수를 구하는 것이 이 문제의 요구사항입니다.

가장 단순한 방법은 모든 조합을 나열하여 직접 비교하는 것입니다. 그러나 낱장 수 `N`의 최대값이 `200,000`이므로 총 숫자쌍의 수는 다음과 같습니다.
$$\frac{N(N-1)}{2} = \frac{200,000 * 199,999}{2} = 19,999,900,000$$

이는 연산 횟수로도, 메모리로도 감당할 수 없는 크기이므로 각 쌍을 하나씩 확인하지 않고 **한꺼번에 카운트**하는 방법이 필요했습니다.

## 1. 관점 바꾸기
숫자쌍 자체를 확인하는 대신, 각 낱장의 위치에 집중하는 쪽으로 생각을 바꿨습니다.

> 어떤 낱장 하나를 **왼쪽 원소**로 고정한다.
> **그 낱장보다 오른쪽에 있으면서 왼쪽 낱장보다 번호가 작은 낱장의 수**가 왼쪽 낱장이 만들어내는 엇갈린 쌍의 수이다.

이 값을 모두 더해 낱장에 대해 구한 뒤 더하면 전체 답이 됩니다.
따라서 이 문제의 핵심 요구사항은 "**오른쪽에 있으면서 나보다 작은 낱장의 개수를 어떻게 빠르게 셀 것인가**"입니다.

## 2. 조건 하나를 순서 변경으로 해결하기
두 조건 중 하나인 **나보다 작은 것**을 처리 순서 변경으로 대신하면 남은 한 조건만 신경쓸 수 있게 됩니다. **낱장 번호가 큰 것부터** 처리한다고 하면 각 낱장을 처리하는 시점에 자기보다 오른쪽에 있는 모든 낱장은 왼쪽 낱장보다 작은 상태가 됩니다.

따라서 **왼쪽 낱장 뒤부터 마지막까지의 구간 내 낱장의 개수**만 세면 그것이 곧 **왼쪽 낱장이 만들어내는 엇갈린 쌍의 수**가 됩니다.

이 과정을 구현하기 위해 남은 할 일은 **구간별 낱장의 수를 관리하는 동시에 변경점을 빠르게 갱신할 수 있는 구조를 만들어내는 것** 뿐입니다.

## 3. 구간합 세그먼트 트리
위 과정의 해결을 위해 구간합을 관리하는 동시에 이미 사용한 낱장을 제거하는 상황에도 빠른 갱신이 가능한 "**구간합 세그먼트 트리**"를 채택했습니다.

세그먼트 트리의 각 리프 노드에는 낱장이 남아 있으면 1, 없으면 0으로 초기화합니다.
그리고 각 상위 노드에는 두 하위 노드의 값을 합친 구간합을 저장합니다.

또한 탐색 및 갱신을 위해 2가지 질의를 요구합니다.
- **구간 질의 :** 최대값인 낱장의 위치부터 끝까지의 남은 낱장 개수 -> $O(\log N)$
- **점 갱신 :** 이미 사용한 최대값 낱장을 0으로 변경하고 구간합 갱신 -> $O(\log N)$
