# 48. 쓸모 있는 터널


## 문제 분석
물류 센터 `N`개와 양방향 터널 `M`개가 주어지며 각 터널마다 소요 시간이 주어집니다. 출발 센터 `S`와 도착 센터 `T` 두 센터 간 이동 시 소요 시간이 제일 짧은 경로를 "**최속 경로**"라고 부르며 **최속 경로의 소요 시간**을 구해야 합니다. 기본적인 다익스트라 로직으로 구할 수 있을 것입니다.

그러나 "**쓸모 있는 터널**"의 개수도 구해야 합니다. 최속 경로가 여러 개일 수 있고, 그 중 하나에라도 속한 터널을 모두 "**쓸모 있는 터널**"이라고 부릅니다. 따라서 최속 경로에 속하는 모든 터널의 번호를 알고 있어야 한다고 생각했습니다.

이를 위해 다익스트라에 사용할 `Node` 클래스에 터널 번호를 저장하는 `List`를 관리해야 하나 생각했으나, 센터의 수도 `100,000`, 터널의 수도 `200,000`으로 적지 않기에 매 루프마다 리스트를 새 노드에 옮기고 관리하는 로직을 짜는 것은 말이 안된다고 판단했습니다.

대신 다익스트라를 거치면 최속 경로의 소요 시간은 바로 알 수 있으니, 이를 단서로 잡고, 각 터널마다 한 가지 검증을 거치면 그 터널이 최속 경로에 속하는 지 판단할 수 있을 것으로 보았습니다.


### 1. 각 터널의 소요 시간 == 최속 경로의 소요 시간 - 나머지 경로의 소요 시간
각 터널의 소요 시간은 입력값으로 주어지므로, 이를 미리 저장했다가 다익스트라 이후 최속 경로를 구성하기 위해 각 터널을 제외한 나머지 경로는 어느 정도의 소요 시간이 필요한 지 계산할 수 있습니다.
<br>
최속 경로가 `10`이고, 현재 검증하는 터널의 소요 시간이 `2`라면 나머지 경로의 소요 시간은 정확히 `10-2=8`이어야 합니다.


### 2. 반드시 지나는 터널이라고 가정하기
검증 과정에서 각 터널을 "**반드시 지나는 터널**"이라고 가정하면 출발 센터 `S`와 도착 센터 `T`도 정해져 있으므로 다음과 같은 흐름을 만들어낼 수 있습니다.
- 각 터널의 두 입구를 `a`와 `b`라고 한다.
- 해당 터널을 반드시 지나는 경로의 소요 시간은 `(S -> a) + (a -> b) + (b -> T)`이다.
- 최속 경로의 소요 시간 `x`는 다익스트라를 통해 구할 수 있다.
- 따라서 검증 과정에서 각 터널을 제외한 나머지 경로의 소요 시간은 `x - (a -> b) == (S -> a) + (b -> T)`이다.

### 3. (b -> T) 구하기
위 가정을 통해 이 문제를 해결하기 위해 무엇을 구해야 할 지 정해졌습니다. `(S -> a)`는 출발 센터 기준 다익스트라를 통해 구할 수 있지만, `(b -> T)`를 구할 수 없습니다.
<br>
따라서 도착 센터 기준 다익스트라를 수행하여 `(T -> b)`를 구하면 무방향 그래프이므로 반대 방향인 `(b -> T)`의 소요 시간도 동일하게 적용할 수 있습니다.


## 설계 및 구현


### 1. 터널 및 경로 상태 정의 : Node 클래스
```java
static class Node implements Comparable<Node> {
    int id;
    long cost;

    public Node(int id, long cost) {
        this.id = id;
        this.cost = cost;
    }

    @Override
    public int compareTo(Node o) {
        return Long.compare(this.cost, o.cost);
    }
}
```

인접 리스트 및 다익스트라에 활용할 `Node` 클래스입니다.
<br>
각 `Node` 객체는 현재 센터 기준 터널이 향하는 다음 센터의 번호와 소요 시간을 관리합니다. 또한 소요 시간 오름차순으로 정렬 기준을 재정의하여 우선순위 큐의 정렬 기준을 변경합니다.


### 2. 다익스트라
```java
static PriorityQueue<Node> q = new PriorityQueue<>();
static List<Node>[] graph;

static void dijkstra(int first, long[] dist) {
    q.clear();
    q.add(new Node(first, 0));
    dist[first] = 0;

    while (!q.isEmpty()) {
        Node cur = q.poll();
        if (cur.cost > dist[cur.id]) continue;

        for (Node next : graph[cur.id]) {
            long newCost = cur.cost + next.cost;
            if (dist[next.id] <= newCost) continue;

            dist[next.id] = newCost;
            q.add(new Node(next.id, newCost));
        }
    }
}
```

문제 분석을 통해 총 2번의 다익스트라(출발 센터 기준, 도착 센터 기준)가 필요하다고 판단하였습니다. 이에 따라 **최단 소요 시간을 저장하는 배열이 각 다익스트라 수행마다 별도로 요구**되며 차후 터널 검증을 위해 각 터널의 정보를 **인접 리스트 외 별도 공간에 저장**할 필요가 있었습니다.

총 2번의 다익스트라를 수행하여 출발 센터로부터의 소요 시간, 도착 센터로부터의 소요 시간을 각각 기록합니다. 각 메서드 호출마다 다른 소요 시간 배열을 사용하므로 코드 재사용성을 위해 배열을 매개변수화 하였습니다.


### 3. 최속 경로의 소요 시간 확정
```java
long minCost = distByStart[end];
if(minCost == Long.MAX_VALUE) {
    System.out.println("-1");
    return;
}
```

최속 경로의 소요 시간은 다익스트라를 통해 바로 확정할 수 있습니다. 또한 출발 센터에서 도착 센터에 도달할 수 없는 입력값이 주어질 수 있음에 유의하여 예외 처리를 수행하였습니다.


### 4. 터널 검증
```java
int cnt = 0;
for(int i=0; i<e; i++) {
    long needCost = minCost - nodeCost[i];
    if(distByStart[startIdx[i]] + distByEnd[endIdx[i]] == needCost
            || distByEnd[startIdx[i]] + distByStart[endIdx[i]] == needCost) cnt++;
}
```

각 터널이 최속 경로에 속하는 지 알아내려면, 역으로 "**각 터널을 반드시 지나야 한다고 가정했을 때 나머지 경로의 소요 시간**"을 구하면 됩니다.

최속 경로의 소요 시간 `(S -> T)`과 각 터널의 소요 시간 `(a -> b)`를 알고 있으므로 다음 공식이 성립한다면 해당 터널은 최소 경로에 속한다고 할 수 있습니다.
- $t(S, T) = t(S, a) + t(a, b) + t(b, T)$
- $t(S, T) = t(S, b) + t(b, a) + t(a, T)$

무방향 그래프이니 둘 중 하나만 성립해도 최속 경로에 속한다고 할 수 있습니다.
