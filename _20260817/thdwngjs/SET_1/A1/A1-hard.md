# 가장 위험한 터널 해설

## 문제 요약

가중치 트리에서 두 정점을 잇는 경로 위 간선의 최대 가중치와, 그 최댓값과 같은 가중치를 가진 간선의 개수를 질의마다 구한다.

## 관찰

경로를 실제로 따라가며 최댓값을 세면 질의당 $O(N)$이라 $10^{10}$번이 된다. 그런데 A2에서 본 것처럼 경로는 "$u$에서 LCA까지 올라가는 구간"과 "$v$에서 LCA까지 올라가는 구간" 둘로 쪼개진다. 그러니 **위로 올라가는 구간에 대한 정보만 빠르게 얻으면** 된다.

희소 배열은 원래 $2^j$칸 위 조상 번호를 담는 표였다. 여기에 값을 하나 더 얹을 수 있다는 게 이 문제의 전부다. $mx[j][v]$를 "$v$에서 $2^j$칸 올라가는 동안 만나는 간선 가중치의 최댓값", $cn[j][v]$를 "그 구간에서 최댓값과 같은 가중치를 가진 간선의 개수"로 두면

$$mx[j][v] = \max(mx[j-1][v],\; mx[j-1][mid]), \qquad mid = up[j-1][v]$$

로 채워진다. 개수는 조금 더 조심해야 한다. **두 조각의 최댓값이 같을 때만 개수를 더하고, 한쪽이 크면 그쪽 개수만 가져온다.** 이 규칙 하나가 이 문제의 난이도를 만든다.

$$cn[j][v] = \begin{cases} cn[j-1][v] & (mx[j-1][v] > mx[j-1][mid]) \\ cn[j-1][mid] & (mx[j-1][v] < mx[j-1][mid]) \\ cn[j-1][v] + cn[j-1][mid] & (\text{같을 때}) \end{cases}$$

이 병합은 결합법칙을 만족하므로(최댓값과 그 개수는 어떤 순서로 묶어도 같다) 조각들을 순서에 상관없이 합쳐도 된다. 그래서 LCA를 구하는 과정에서 지나치는 모든 조각을 그때그때 답에 합쳐 넣기만 하면 된다.

## 풀이

LCA를 구하는 절차를 그대로 쓰되, 점프할 때마다 그 조각의 $(mx, cn)$을 누적한다.

1. 깊이를 맞추며 올라갈 때: 켜진 비트 $k$마다 $(mx[k][u], cn[k][u])$를 합치고 $u \leftarrow up[k][u]$.
2. 함께 올라갈 때: $up[k][u] \ne up[k][v]$이면 양쪽 조각을 모두 합치고 둘 다 올린다.
3. 마지막으로 LCA 바로 아래 남은 두 간선 $(mx[0][u], cn[0][u])$, $(mx[0][v], cn[0][v])$를 합친다.
4. $u = v$인 질의는 지나는 간선이 없으므로 곧바로 `0 0`.

공개 샘플의 $u=4$, $v=7$을 따라가면 조각들이 $(7,1)$, $(5,1)$, $(9,1)$, $(9,1)$, $(2,1)$ 순으로 합쳐진다. 최댓값 $9$가 두 번 등장하므로 답은 `9 2`다. $u=1$, $v=5$는 가중치 $5$짜리 간선 두 개만 지나므로 `5 2`가 된다. 최댓값이 같을 때 개수를 더하는 규칙을 빠뜨리면 이 두 질의에서 바로 틀린다.

```java
static void take(long m, int c) {
    if (m > bestMax) { bestMax = m; bestCnt = c; }
    else if (m == bestMax) bestCnt += c;   // 같으면 더한다
}
```

전체 자바 코드는 `java/A1-Solution.java` 참고.

## 복잡도

- 시간: 표 만들기 $O(N \log N)$, 질의당 점프 $O(\log N)$ → 전체 $O((N+Q)\log N)$.
- 공간: $O(N \log N)$. 가중치는 long, 개수는 int면 충분하다. $N=10^5$, $LOG=17$이면 long 배열 약 $1.7\times10^6$칸(약 14MB)이라 메모리 제한 안에 든다.

## 구현 노트

- 가중치가 $10^{12}$까지라 `int`로 받으면 넘친다. 배열과 비교 변수 모두 `long`이어야 한다. 반면 개수는 최대 $N-1$이라 `int`로 충분하다.
- 초기 최댓값을 $0$으로 두고 개수를 $0$으로 두면, 가중치가 항상 $1$ 이상이므로 빈 구간이 자연스럽게 항등원으로 작동한다. 뿌리의 $mx[0][1]=0$, $cn[0][1]=0$을 꼭 그렇게 맞춰 둔다.
- 검증기는 희소 배열 대신 HLD + 세그먼트 트리로 같은 답을 낸다. 병합 규칙을 "개수는 무조건 더한다"거나 "최댓값만 갱신"으로 잘못 짜면 두 구현의 답이 갈린다.

## 흔한 실수

- 최댓값이 같을 때 개수를 더하지 않고 덮어쓰기. 가중치가 전부 같은 데이터(예: 모든 터널이 $10^{12}$)에서 즉시 드러난다.
- $u = v$ 질의에서 `0 0` 대신 아무 값이나 출력하거나 예외 발생.
- 가중치를 `int`로 읽어 오버플로.
- LCA 바로 아래 남은 두 간선을 합치는 마지막 단계를 빼먹기. 랜덤 데이터에서는 자주 맞는 것처럼 보인다.
