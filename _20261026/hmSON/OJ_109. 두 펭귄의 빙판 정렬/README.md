# OJ_109. 두 펭귄의 빙판 정렬

판을 기울이면 두 펭귄이 동시에 같은 방향으로 미끄러질 때, 1번 펭귄을 A에, 2번 펭귄을 B에 동시에 멈추게 하는 최소 기울이기 횟수를 구해야 함

기울이기 한 번이 곧 한 단계이고 모든 단계의 비용이 동일하므로 **BFS**로 접근<br>
다만 두 펭귄이 함께 움직인다는 점에서 두 가지 문제가 생김

> 1. 두 펭귄이 같은 칸에 도착하려는 경우를 어떻게 처리할 것인가
> 2. 방문 처리를 어떤 단위로 할 것인가

코드 내에서는 편의를 위해 입력의 펭귄 1, 2를 펭귄 0, 1로 지칭


## 1. 방문 처리 단위 확장
한 펭귄의 위치만으로 방문 처리를 하면 정답을 놓침

> **같은 칸이라도 상대 펭귄의 위치에 따라 이후 전개가 완전히 달라지기 때문**

예시에서 1번 펭귄은 목표 칸인 A를 두 번 거치게 됨<br>
첫 번째 방문에서 방문 처리를 해버리면 두 번째 경로가 막혀 최소 횟수를 구할 수 없음

따라서 방문 처리의 단위를 **두 펭귄의 위치 쌍**으로 확장

> `visited[펭귄 0의 위치][펭귄 1의 위치]`

격자가 최대 `50 × 50`이므로 한 펭귄의 위치는 최대 2,500가지, 쌍으로는 약 625만 가지<br>
모든 좌표를 `y * c + x` 형태의 1차원 값으로 압축하면 배열 차수를 2차로 유지할 수 있음


## 2. 겹침 처리 - 맵 변경 대신 사후 보정
두 펭귄이 같은 줄에서 같은 방향으로 미끄러지면 뒤쪽 펭귄이 앞쪽에 막혀 멈춤

하위 문제에서는 맵에 펭귄 위치를 직접 기록하고 앞쪽 펭귄부터 순차 이동시키는 방식을 사용했으나, BFS에서는 적합하지 않음

> **BFS는 상태를 큐에 쌓아두고 나중에 꺼내므로, 그 시점의 맵은 이미 다른 상태로 변해 있음**

따라서 맵을 전혀 건드리지 않는 방식으로 변경

1. 두 펭귄의 충돌을 무시한 채 각각 벽까지 미끄러뜨림
2. 도착점이 같다면 뒤쪽 펭귄만 한 칸 보정

보정 위치는 겹친 칸에서 **진행 방향의 반대로 한 칸 되돌린 지점**


### 2-1. 앞뒤 판별 - 방향 벡터 투영
어느 펭귄이 뒤쪽인지 판별해야 하는데, 방향마다 조건을 나누면 네 가지 분기가 필요함

대신 **진행 방향 벡터에 좌표를 투영**하면 하나의 식으로 처리 가능

```java
int proj0 = (curP0/c) * dy[i] + (curP0%c) * dx[i];
int proj1 = (curP1/c) * dy[i] + (curP1%c) * dx[i];
```

투영값이 클수록 진행 방향 기준 앞쪽에 위치하므로, **작은 쪽을 보정**하면 됨<br>
위쪽은 `dy = -1`이라 행 번호가 작은 쪽이 큰 투영값을 갖고, 아래쪽은 그 반대가 되는 식으로 네 방향이 한 식에 흡수됨


## 3. 복잡도
- 상태 수 : 두 펭귄 위치의 조합이므로 $O((HW)^2)$
- 각 상태의 전이 : 네 방향 × 미끄러짐 거리 → $O(\max(H, W))$

전체 $O((HW)^2 \cdot \max(H,W))$가 상한이지만, 실제로는 미끄러진 결과가 벽 앞 칸으로 수렴하여 도달 가능한 상태 수가 훨씬 적음<br>
`50 × 50` 규모에서는 2초 제한 안에 충분히 들어옴

공간 복잡도는 방문 배열이 지배하여 $O((HW)^2)$, 약 6.25MB 수준
