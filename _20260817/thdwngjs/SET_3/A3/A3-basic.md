# 관측소 통신망 개통 해설

## 문제 요약

관측소 $N$개에 케이블 $M$개를 주어진 순서대로 설치할 때, 모든 관측소가 처음으로 하나로 이어지는 시점의 케이블 번호를 구한다. 끝까지 이어지지 않으면 $-1$이다.

## 관찰

가장 단순한 방법은 케이블을 하나 설치할 때마다 처음부터 그래프를 다시 그려 BFS나 DFS로 "전부 연결됐나"를 확인하는 것이다. 판정 한 번이 $O(N+M)$이고 케이블마다 판정하니 $O(M(N+M))$, 즉 $3 \times 10^5 \times 5 \times 10^5 = 1.5 \times 10^{11}$이다. 손도 못 댄다.

여기서 두 가지를 눈여겨보자.

첫째, **케이블은 지워지지 않고 쌓이기만 한다.** 한 번 같은 무리가 된 두 관측소가 다시 갈라지는 일은 없다. 그러니 무리의 개수는 절대 늘지 않고, 케이블 하나마다 그대로이거나 정확히 $1$만큼 줄어든다. 다시 말해 "전부 연결됐다"는 성질은 케이블 번호에 대해 단조롭다. 한 번 참이 되면 계속 참이다.

둘째, **매번 전체를 다시 볼 필요가 없다.** 알아야 하는 건 무리의 "개수"뿐이지 무리의 구체적인 모습이 아니다. 개수는 $N$에서 출발해 실제로 두 무리가 합쳐질 때만 $1$씩 빼면 유지된다. 그러면 케이블 하나를 처리하는 비용이 "두 관측소가 같은 무리인가"를 묻고 필요하면 합치는 비용으로 줄어든다.

두 번째 관찰을 그대로 옮긴 자료구조가 유니온 파인드(분리 집합)다.

## 풀이

`parent` 배열로 각 무리를 트리 하나로 표현하고, 무리의 대표를 그 트리의 루트로 삼는다.

- `find(x)`: `parent`를 따라 루트까지 올라간다. 올라간 뒤 경로 위 정점들을 루트에 직접 붙여 둔다(경로 압축).
- `union(a, b)`: 두 루트가 다르면 크기가 큰 쪽 밑에 작은 쪽을 붙인다(union by size). 트리 높이가 $O(\log N)$을 넘지 않게 막아 준다.

남은 무리 수 `comp`를 $N$으로 초기화하고 케이블을 $1$번부터 순서대로 본다. `find(u) != find(v)`일 때만 합치고 `comp--`를 한다. `comp`가 $1$이 되는 순간의 번호가 답이고, 반복이 끝날 때까지 그런 일이 없으면 $-1$이다.

자기 루프와 중복 간선을 따로 처리할 필요가 없다는 점이 이 구현의 편한 부분이다. $u = v$면 `find(u)`와 `find(v)`가 같은 값이라 조건문이 자동으로 걸러 주고, 이미 같은 무리인 중복 간선도 마찬가지다. 지문에서 "무리 개수가 줄지 않는다"고 나눠 설명한 두 경우가 코드에서는 한 줄로 합쳐진다.

공개 샘플($N=6$)을 따라가 보면 이렇다.

| 케이블 | 잇는 관측소 | `find(u)`, `find(v)` 가 다른가 | `comp` |
|---|---|---|---|
| (설치 전) | | | 6 |
| 1 | 1 2 | O | 5 |
| 2 | 1 3 | O | 4 |
| 3 | 2 3 | X | 4 |
| 4 | 3 4 | O | 3 |
| 5 | 4 5 | O | 2 |
| 6 | 5 6 | O | 1 → 답은 6 |

`comp`가 $1$이 된 시점에서 바로 멈추므로 $7$번 케이블은 보지도 않는다.

핵심 루프는 이 정도다.

```java
int ru = find(u), rv = find(v);
if (ru != rv) {                       // 자기 루프·중복 간선은 여기서 자동으로 걸러진다
    if (size[ru] < size[rv]) { int t = ru; ru = rv; rv = t; }
    parent[rv] = ru;
    size[ru] += size[rv];
    if (--comp == 1) { ans = i; break; }
}
```

전체 자바 코드는 `java/A3-Solution.java` 참고.

## 복잡도

- 시간: 케이블마다 `find` 두 번과 `union` 한 번. 경로 압축과 union by size를 함께 쓰면 연산 하나가 상각 $O(\alpha(N))$이라 전체 $O((N+M)\alpha(N))$이고, 사실상 선형이다.
- 공간: `parent`와 `size` 배열 $O(N)$. 간선을 저장해 둘 필요가 없어 인접 리스트를 만들지 않아도 된다.

## 구현 노트

- **재귀 `find`는 피하는 게 좋다.** union by size를 넣으면 트리 높이가 $O(\log N)$으로 눌리긴 하지만, 어차피 루트까지 두 번 훑는 반복문으로 쓰는 편이 짧고 스택 걱정도 없다. 첫 번째 훑기로 루트를 찾고, 두 번째 훑기에서 경로 위 정점을 전부 루트에 직접 붙인다.
- **`comp`를 언제 줄이느냐가 전부다.** 케이블마다 무조건 줄이면 자기 루프나 중복 간선에서 개수가 음수로 내려가 엉뚱하게 이른 답이 나온다. 반드시 두 루트가 다를 때만 줄인다.
- **이 문제에는 오버플로가 구조적으로 발생하지 않는다.** 출력은 케이블 번호라 최대 $3 \times 10^5$이고, `size` 배열의 합도 $N \le 2 \times 10^5$을 넘지 않는다. 더할 것도 곱할 것도 없으니 전부 `int`로 충분하고, `long`을 억지로 쓸 이유가 없다.
- 입력이 최대 $30$만 줄이다. `Scanner`로 읽으면 그것만으로 시간이 다 간다. `BufferedReader`를 감싼 `StreamTokenizer`나 직접 만든 바이트 단위 리더를 쓴다.
- 검증기는 유니온 파인드를 쓰지 않고, 간선 번호에 대한 이분 탐색 + 반복문 BFS로 같은 답을 구한다("앞 $k$개만 설치했을 때 연결되는가"가 단조라는 첫 번째 관찰을 그대로 이용한다). 접근이 완전히 달라서, `comp` 갱신 조건을 잘못 잡거나 $-1$ 판정을 빼먹는 실수가 두 출력의 불일치로 바로 드러난다.

## 흔한 실수

- 케이블마다 BFS/DFS로 연결 여부를 다시 확인해 $O(M(N+M))$이 되는 풀이. $N$과 $M$이 각각 $2 \times 10^5$, $3 \times 10^5$인 것은 이 접근을 막으려고 잡은 크기다.
- 자기 루프($u = v$)를 예외로 생각해 따로 `continue` 시키다가, 정작 중복 간선은 그냥 합쳐 버리는 경우. 두 상황 모두 `find` 결과가 같으므로 조건문 하나로 해결된다.
- 답을 찾은 뒤에도 계속 갱신해서 마지막으로 합쳐진 시점을 출력하는 경우. 물어보는 것은 **처음으로** 하나가 되는 시점이다. `comp == 1`이 되면 즉시 기록하고 빠져나온다.
- $-1$ 처리를 빠뜨리는 경우. 케이블을 전부 설치해도 무리가 둘 이상 남을 수 있다. 관측소 하나만 고립돼 있어도 답은 $-1$이다.
- `parent` 배열을 $1$번부터 초기화하지 않거나 크기를 $N$으로 잡아 $N$번 관측소에서 인덱스가 벗어나는 경우. 번호가 $1$부터 $N$까지이므로 배열 크기는 $N+1$이다.
