## 처음 작성한 모델링

### 내가 이해한 문제

송전망을 어디를 끊고 어떻게 이어야 최선의 결과 값을 찾을 수 있는지 잘 모르겠다.

다만 트리 구조라는 힌트를 주었으므로 DFS가 `O(n)`이고 송전망 끊기가 `O(n)`이라고 한다면, 100^100은 10000이므로 시간적으로 문제가 없어 완전탐색을 수행하고자 한다.

### 상태

- 0~n-1 송전망 개수
- DFS할 때 쓸 `visit[]`: 방문했는지 안 했는지
- `count`: DFS할 때 송전탑 개수
- 현재까지 가장 낮은 송전탑의 차이 변수

### 전이

- 아직 방문하지 않았다면 `visit = true`
- 아직 방문하지 않았다면 카운트를 증가시키고 DFS를 실행해서 한 송전탑에서 연결된 모든 송전탑 개수를 센다.
- 하나의 송전선 확인이 끝나면 방문과 카운트를 모두 초기화한다.

### 제약

- 이미 방문한 곳은 건너뛴다.

### 목표

- 특정 송전선을 끊었을 때?

### 내 풀이 방향

- 0~n-1 `for`문 생성
- 방문하지 않았다면 방문 처리
- 네트워크 카운트 증가
- DFS 또는 BFS를 시작해서 연결된 것을 모두 방문 처리
- 탐색 후 다시 `for`문 진행

### 막힌 부분

- 심한 건 아닌데 DFS 부분에서 신경 써야 할 조건들이 있었는데 모델링에는 없어서 다른 구간보다 조금 더 지체된 문제가 존재했다.

## 다시 작성한 모델링

### 내가 이해한 문제

송전망을 어디를 끊고 어떻게 이어야 최선의 결과 값을 찾을 수 있는지 잘 모르겠다.

다만 트리 구조라는 힌트를 주었으므로 DFS가 `O(n)`이고 송전망 끊기가 `O(n)`이라고 한다면, 100*100은 10000이므로 시간적으로 문제가 없어 완전탐색을 수행하고자 한다.

### 상태

- 0~n-1 `Ecount`: 현재 방문한 송전탑 개수
- DFS할 때 쓸 `visit[]`: 방문했는지 안 했는지
- 현재까지 가장 낮은 송전탑의 차이 변수 `minCount`
- `current`: 현재 위치한 송전탑 번호

### 전이

- 외부 송전망 하나하나를 직접 처리
- 내부 잘린 송전망 양 끝단 중 하나에서 출발해서 송전탑 탐색
- 아직 방문하지 않았다면 `visit = true`
- 아직 방문하지 않았다면 카운트를 증가시키고 DFS를 실행해서 한 송전탑에서 연결된 모든 송전탑 개수를 센다.
- 하나의 송전선 확인이 끝나면 방문과 카운트를 모두 초기화한다.

### 제약

- 이미 방문한 곳은 건너뛴다.
- 잘린 전선은 건너지 않는다.

### 목표

- 특정 송전선을 끊었을 때?
- 두 개로 나뉜 송전망 내부의 송전탑 개수의 차가 최소인 곳을 찾기
- `Math.abs(전체 송전선 - 연결된 송전망 개수 * 2)`

### 내 풀이 방향

- 0~n-1 `for`문 생성
- 의도적으로 건너 칸을 방문 처리해서 전선을 끊음
- 방문 초기화
- 카운트 초기화
- DFS 또는 BFS를 시작해서 연결된 것을 모두 방문 처리
- `Math.abs(전체 송전선 - 연결된 송전망 개수 * 2)`
- `for`문 진행
