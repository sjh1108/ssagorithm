# 문제 해석
트리를 만들고 각 정점에서 다른 트리로 분리가 될때 가장 작은 서브트리가 되는 노드 X를 찾는 문제같은데?

# 문제 풀이
## 루트의 필요성
그러면 트리 문제 같은데 정확한 루트가 필요한가?
루트는 1로 잡고 트리를 만들어도 괜찮을 것 같은게
딱히 루트나, 입구에 대한 언급이 없으니 1번 노드를 루트로 잡고, 1번 노드로 연결되는 노드들을 가지로 생각해도 결과의 차이는 없을 것 같다.
결국 각 서브트리의 합을 찾는 것이기 때문임

## 트리의 구성
그렇다면 1번 노드를 루트로 생각하기로 했기 때문에, 각 노드는 깊이를 DFS를 통해서 알 수 있다. 연결되어 있는 상위 노드보다 depth를 +1 해서 생각하면 되기 때문임

## 함정
근데 DFS를 재귀로 추적하면 N이 100,000 까지 되기 때문에 Stack Overflow가 날 가능성이 있다. 따라서 반복적인 DFS를 통해서 해결해야 할 것으로 보인다.

# 코드 구성
## 서브 트리의 합 연산과 f(v) 초기값 구성
방문한 역순으로 서브트리의 합을 계산하고, 해당 값에서 최댓값을 도출하면 된다.
우선 서브트리의 합은 역순으로 올라가면서 계산하면, 해당 노드 v의 f(v) 초기값은 총합에서 리프 서브트리 합을 합치면 된다.

## f(v) 연산
이후 각 노드를 돌며 해당 노드에서의 f(v) 값을 연산하면 된다.
sub[] 배열을 이용해서 순회를 돌며, 연산해둔 서브 트리의 합을 통해 f(v)의 값을 연산한다.

## 마무리
이제 각 노드별 f(v) 값이 연산되었으니 f(v)의 최소값을 갖는 노드와 최소값을 출력한다.

# 함정 및 어려움
1. DFS를 통해 트리를 구성하는 경우 스택 오버플로우가 날 가능성에 대한 생각을 해본게 처음인지라 코드 구성에 많은 힘이 들었다.
2. 서브트리의 합을 연산하는 과정에서도 고뇌가 조금 필요했는데, 상위 노드를 위한 연산을 초기값으로 설정하는 아이디어 없이는 연산에 조금 힘이 들었을 것 같다.
